# ランタンの光が二枚の壁を経由して天井を照らす

Aqualumen 1.9.0-preview.7 は近くの地形で、ランタンや松明の光が二度拡散反射して届く色を計算する。ランタンの東側だけを開けた黒い筒を造り、光を壁Aに当てる。壁Aを見渡せる北向きの壁Bを置き、天井は壁Aの裏側まで張り出させた。プレイヤーから見えない壁Aの材質も、天井の色に影響する。[配布ZIP](../../dist/Aqualumen-1.9.0-preview.7.zip) · [ゲーム内の配置とカメラ](ordinary/geometry.json)

## どこで光を計算するか

地形の各ブロック面を四分割する。一枚目の壁から受けた光は既存の計算結果を使う。二度目の反射では、天井の各点から、面に垂直な方向ほど密になる96本の光線を出す。最初に当たった面がこちらへ返す色は、そこで受けた光と、そのブロックのアトラスから取得した線形RGB反射率の積で求める。ガラスや葉を通過した光には、その区間の透過率を掛ける。独立したテクスチャ領域にこの寄与を書き、直射・一回反射・日光からの寄与と合わせる。カメラ周辺32ブロックの格子、1区間最大12ブロック、拡散面の有限サンプル近似である。[計算シェーダー](../../release/ceiling-preview/shaders/shadowcomp4.csh) · [受光面での合成](../../release/ceiling-preview/shaders/lib/bounce_receiver.glsl)

外部で参照したRethinking Voxelsは、作者がボクセル化した地形の光線遮蔽と色付きブロック光の伝播を説明している。Aqualumenでは自作の格子と拡散面を使い、反射が一回・二回の各寄与を個別に出力して遮蔽物と材質の効果を測った。[Rethinking Voxels](https://github.com/gri573/rethinking-voxels) · [Photonの拡散光処理](https://github.com/sixthsurge/photon/blob/a715d94b45121e0825e40ba0029276b4378ce65d/shaders/include/lighting/diffuse_lighting.glsl) · [PBRTの光輸送方程式](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/The_Light_Transport_Equation)

## Minecraftで壁材と光路を変える

Minecraft 1.21.1、Iris 1.8.8、RTX 3080 Tiで、カメラを固定し、各条件で378マスと視点を照合した。表の中央二列は配布版で撮った天井中央21×21画素の平均表示RGBを丸めた値。右列は同じ位置に最も近い計算点の二回反射で、個々の成分を `255 × √(64 × 線形光量)` で符号化した診断画像から読んだ。通常画面の差は数階調で、直射の届かない天井に弱く返る。[8条件の通常画面](ceiling.jpg) · [各点の値と表示画像のハッシュ照合](measurements.json)

| 操作 | 前版の表示RGB | プレビュー7の表示RGB | 二回反射の診断RGB |
| --- | --- | --- | --- |
| 壁A・Bとも白 | 68, 70, 88 | 72, 72, 89 | 55, 40, 25 |
| 壁Aを赤にする | 68, 70, 88 | 70, 70, 88 | 36, 5, 3 |
| 壁Bを灰色にする | 68, 70, 88 | 68, 70, 88 | 13, 10, 7 |
| ランタンを撤去 | 71, 71, 89 | 71, 71, 89 | 0, 0, 0 |

元の白い壁に戻すと、天井三点の二回反射はすべて元の値に戻った。中央の直射は全条件で測定下限。壁間を黒いコンクリートで塞いだ場合には、二回反射が (4, 3, 3) 残った。通常の白壁でも一回反射は中央で (4, 4, 3) あった。天井の直下を塞いだ写真では、カメラは仕切りの下面を見ている。[通常描画の検証](ordinary/complete.json) · [明るさを光路別に読み出した検証](meter/complete.json)

さらに、天井を覆わず横から縦壁を建てた。壁Bの三点が受けた光量と天井の計算対象面は前後で一致した。天井三点の二回反射の赤成分は、診断画像で手前から 65→62、55→4、41→0。線形光量に戻すと、それぞれ元の約91%、0.53%、測定下限になった。光を返す壁が同じでも、そこから天井のどの部分が見えるかで結果が変わる。[仕切りを入れる前](side-meter/white-ingame.png) · [仕切りを入れた後](side-meter/screen-ingame.png) · [同一条件の照合](side-meter/complete.json)

## 面積積分とGPUでの照合

点光源の放射強度と二つの壁の拡散反射率を1にした。床置きランタンの中心をブロック底から0.50 mに置くと、二回反射して天井三点に入る照度は0.00015118、0.00011195、0.00005433になった。1 mあたりの分割数を16から32に増やしたときの差は最大0.043%。光源の高さ0.44 mで取った先行基準も残した。[床置きランタンの積分値](lantern-reference.json) · [高さ0.44 mの先行値](reference.json) · [計算コード](reference.py)

実際のGLSLをRTX 3080 TiとMesaで走らせた。白い壁2枚でのRTXの赤成分は0.002476、0.001748、0.000985。パックの光源強度を合わせた点光源の面積積分との比は1.30、1.24、1.44で、最大44%強く出た。シェーダーには有限の光源半径・近距離減衰・半ブロックの面サンプル・有限方向の積分がある。壁Aを赤くしたときと、壁Bだけを暗くしたときに、それぞれの反射率に応じて二回反射のRGBが下がった。[RTXでの面別の読み出し](ceiling-nvidia.log) · [Mesaでの読み出し](side-mesa.log)

黒い仕切りを入口・壁の間・天井の裏に個別に入れると、理想黒のGPU実験ではそれぞれ三点ともゼロになった。さらに天井を露出したまま、その横に縦壁を一枚建てた。独立したCPU積分では一点目に95.3%が残り、残り二点がゼロになる。最初の検査では二点に残ると想定したが、そのうち一点は既存の壁と新しい縦壁で光路が閉じる。積分とGLSLの両方で位置を確認した。[縦壁の位置と残る光量](side-screen.json) · [GPUでの再現手順](../../tools/ceiling-light-probe.h)

通常のビルドは `python3 tools/build.py --ceiling-preview`、二回反射の検査は `make check-ceiling`。既存の地面反射・動物の頂点照明・通常プレイのGPU回帰検査も行った。配布パックの差分はシェーダーと設定の4ファイルである。[再ビルド照合](packages.json) · [地面](ground-regression.log) · [動物](animal-regression.log) · [通常プレイのGPU回帰](regression-nvidia.log)

## 雪村に帰って灯りを置く

自然生成された雪の村のセーブを、雨の平原、時刻22264から再開した。朝を迎え、151.28 m歩いて戻ったトウヒの家には屋根のランタンと玄関の二灯があり、魂の松明を床に置くと、青い光が梁と寝台の周りに届いた。普通のサバイバル、コマンド無効、時刻と天気は自然に進む。配布するワールドZIPを検証用の別のセーブフォルダに展開し、同じ家の中から実際にMinecraftを再開した。[帰路と家の写真](village/homecoming.jpg) · [帰還の抜粋映像](village/homecoming.mp4) · [歩行と保存・終了の記録](village/homecoming/complete.json)

保存した魂の松明を外したときと置き直したときでは、同じ梁の平均表示RGBが (74,62,38) → (68,37,18) → (73,61,38) と変わった。壁やランタンを壊さず、同じ床に松明が戻ったことを保存ファイルからも確認した。[三枚の実ゲーム写真](village/relight.jpg) · [測定箇所](village/relight.json) · [ZIPからの再開・撤去・再設置](village/archive-revisit/complete.json)

家を試すにはワールドZIPを展開し、中の `Aqualumen-Homecoming` フォルダをMinecraftの `saves` に入れる。床の魂の松明を外し、3番スロットにある魂の松明を同じ場所に置き直せる。オーク林の遠征セーブも保存した。どちらも元のスターターワールドとフォルダ名を分けた。[雪村の家](../../dist/Aqualumen-Homecoming.zip) · [家とランタンの保存照合](village/homecoming/save.json) · [遠征中のオーク林](../../dist/Aqualumen-Woodland-Expedition.zip) · [今回の連続プレイ日数](playtime.json)

## 窓を移すと、灯りの見え方はどう変わるか

上の家を通常のサバイバルで続けて遊んだ。裏のガラス板を外してトウヒの板で埋め、木の斧で玄関脇の原木を一本抜いた。改築後のセーブを開き直し、玄関の階段を下りて、新しい窓を板で塞いでから開け直した。前庭の同じ座標から、板の向こうの室内が隠れ、再び見える。最後の写真には落下したブロックと室内の動くものが写り込むため、窓中央の画素を明るさの復元率の根拠には使っていない。[改築前後の実画面6枚](village/windows.jpg) · [実際に保存された窓・照明・画素](village/windows.json) · [玄関側から遊べる改築後のセーブ](../../dist/Aqualumen-Window-House.zip)

元の窓を板で塞いだ後、ランタンと魂の松明が残る梁の表示RGBは (73, 61, 38) から (79, 66, 41) になった。反対側の軒下に窓を開けても、同じ梁は (79, 66, 41) のままだった。二つの窓が担う昼光の割合や露出順応は、この自然に時刻が進む三枚からは分離できない。次は屋外と室内を往復し、入射光と露出倍率を別々に時系列で測る。今回の森と村で実際に進んだ重複のない区間は合計29,543ティック、徒歩322.52 m。[改築の操作と保存記録](village/window-move/complete.json) · [外側から再確認した記録](village/porch-window/complete.json) · [プレイ日数の内訳](playtime.json)
