# 設置松明が白樺の後ろに落とす半影

RTX 3080 Ti、Minecraft 1.21.1、Iris 1.8.8、Sodium 0.6.9、lighting compiler 0.3.0 で調べた。設置した松明で、一本の幹が火の一部だけを隠す場所を滑らかにした。床では松明の暖色が木陰に届き、幹の奥には光の届かない領域が残る。動物対応版は `python3 tools/build.py --placed-penumbra-animal-study` でビルドできる。[配布ZIP](../../dist/Aqualumen-Placed-Penumbra-Animal-Study.zip)・[影の縁の比較](animal-ordinary-wall.png)・[牛が横切る実画面](animal-movement.jpg)

## 林の中で見つかった筋

自然の白樺林の草地に松明を4本置いた。最初の試作は、受光する1 m角のセルと松明を囲む直方体に、単純な不透明ブロックだけが入るときに半影を解析的に求めた。Claude Fable は、隣のセルが従来の3本の光線に戻る場所に筋が出ると予測した。実際、草ブロック2個が直方体の端に入るため、照らされている地面の2画素のうち片方だけで計算法が変わった。[アドバイザーの指摘](answer.txt)・[実画面の同じ場所を横切る可視率](forest-edge.png)

| 同じ松明と地面の2画素 | 1画素目 | 隣の画素 |
| --- | ---: | ---: |
| 独立した8,192本の光線による参照 | 30.53% | 34.91% |
| 以前のキャッシュ版 | 66.67% | 66.67% |
| 最初の試作 | 66.67% | 34.90% |
| 修正版 | 30.59% | 34.90% |

修正版は、受光セルのどこかと火の円盤のどこかを結ぶ線分が、そのブロックに届き得るかを判定する。どの線分も届かない2個の草ブロックを除くと、両画素で白樺の幹だけが残る。実際に遮る形はワールド座標と松明の組ごとにVRAMに保存し、各画素で円盤の見える面積を計算する。隣の照明区画では同じ松明の位置・種類・強さを照合する。複雑な遮蔽物が隣に残る部分では、同じ三つの光線による値へ連続的に移行する。[形状の判定](../../release/placed-penumbra-study/shaders/shadowcomp6.csh)・[画素での照明](../../release/placed-penumbra-study/shaders/lib/local_lighting.glsl)

## 独立した参照との比較

ゲーム内のF2画像に、同一フレーム・同一光源の旧方式と試作の可視率、照明の分岐と受光位置を記録した。可視率は8ビットで、画面下端の0～255の全階調を読み戻して確認した。CPU側では元のワールドのブロックを読み、円盤上の8,192点と受光位置を結ぶ線分がどの立方体に当たるかを倍精度で判定した。葉・水・草の形状を確定できない光路は精度集計から除いた。参照値が0.5%から99.5%の間にある地点を半影とした。[参照計算](disk_reference.cpp)・[フレームと位置の対応](compare.py)

- 1440pの白樺林では、4灯合計25,727件の比較可能な半影で平均絶対誤差が11.35ポイントから5.78ポイントに減った。1画素に複数の松明が届く場合は光源ごとに数えた。[光源別の結果](hull-seams.json)
- 混在する計算法の境目で、隣接2画素の可視率差と参照値の差を比べた。初期試作か修正版で経路が切り替わる縦方向2,076組のうち、以前の方式より2/255を超えて悪化した箇所は23組から0組になった。別の実ゲーム収録では実際の光線始点を記録し、横方向の混在境界106組でも該当は0組だった。境目の絶対誤差は一部に残る。[縦方向](hull-seams.json)・[横方向と実際の法線バイアス](horizontal.json)
- 木の葉の屋根、草の床、白壁を備えた隔離区画で、幹の設置・横移動・復帰・伐採・消灯を同じカメラで比較した。床の半影390地点の誤差は13.27→0.12ポイント、壁の1,956地点では18.05→1.10ポイント。白壁に映った影の左縁を横切る214走査線では、隣接画素の最大表示輝度差が平均14.94→3.23階調に減った。照らした草を比べると、松明を置いた直後の表示輝度上昇は中央値49.03階調。幹の設置で暗くなり、伐採後に元の全透過へ戻った位置を床1,310点・壁9,446点で確認した。消灯後の表示輝度と設置前の差は中央値で床0.72・壁1.21階調だった。[9場面の実機記録](grove-release/complete.json)・[光源の配置変更](room-edits.json)・[半影の測定](grove-hull-meter-score.json)
- 実機で使った計算シェーダーをRTXとMesa llvmpipeの両方で、同じ21段階の合成入力に適用した。各レンダラーで受光セルと光源の組975,872件、保存された直方体31,793件を検査した。光源の除去、並べ替え、幹をガラスに変更、木の積み重ね、世界座標の循環、円盤の光路の外と内にあるブロックの編集で、保存された箱の有無と座標が独立した走査に一致した。[RTX](hull-cache-10_nvidia.log)・[Mesa](hull-cache-50_mesa.log)・[参照コード](hull_oracle.py)

## 夜の草地に松明と原木を一つずつ置いた試験

Claude Fableの再レビューを受けて、半影が1ブロックの途中で終わる条件を作った。時刻18,000の平らな草地に松明を1本置き、原木を斜めを含む5か所に置き直した。ゲーム内で受光位置と光線の始点を読み取り、8,192本の光線で求めた値と照合した。5配置の半影21,143地点で可視率の平均絶対誤差は従来13.36ポイント、修正後0.10ポイント。セル境界をまたぐ隣接画素の可視率差を縦303組・横218組で調べると、参照との差が2/255を超えたのは従来314組、修正後0組だった。[アドバイザーの指摘](followup-answer.txt)・[5配置の結果](one-block.json)・[横方向を追加収録した3配置](one-block-horizontal.json)

原木の半影が終わった先で、両画素から火の全面が見える隣接ペアも調べた。各配置で縦・横の両方に測定点を確保し、縦366組・横342組で余分な段差は検出されなかった。元の自然林の半影25,727件については、形状を保存できた13,583件の平均誤差は1.11ポイント。従来の光線計算を使った残り12,144件は11.00ポイントで、全絶対誤差の約90%がこちらに集中した。次に画質を詰める対象は、葉を含む複雑な光路である。葉を通る光の可視率については、今回の独立参照による精度評価は未実施である。[全配置の縦横集計](verification-animal.json)・[白樺林の計算法別集計](forest-residuals.json)

## 幹の横を牛が歩くとき

幹を立てたまま、松明の反対側に牛を出すと、牛の影が届かない壁まで明るさが変わる不具合が見つかった。地形の半影を計算する最初の版では、牛を囲む判定範囲に光路が入ると、壁の1,513地点のうち1,495地点で可視率が2/255を超えて変わった。平均変化は17.68ポイントで、牛がいなくなると元の値に戻った。[修正前の実機測定](animal-overlap.json)

動物対応版では幹が隠す火の面積を保ち、残った部分を通る光線に対してそのフレームの動物の三角形を調べる。遠い側を牛が歩く試験では、同じ壁の1,513地点すべてで可視率が牛の登場前と一致した。逆に松明と幹の間に牛を入れると、元から半影だった2,919地点でさらに暗くなった。可視率の低下は平均40.48ポイント。移動する牛と静止した地形を組み合わせた実機試験で、動物が遮る面積の絶対精度は別途評価が必要である。[修正後の実機測定](animal-joint.json)・[4場面の撮影記録](cow-and-trunk-joint/complete.json)・[実装](../../release/placed-penumbra-animal-study/shaders/lib/local_lighting.glsl)

## フレーム時間とメモリ

動物対応版の配布用ZIPを1440p、12チャンク、松明4本の白樺林で動かし、GPUタイムスタンプを無効にして147フレームを測った。平均フレーム間隔は68.43 ms（約14.6 FPS）、P99は74.38 ms。以下の地形版・従来版も同じ条件で各1回測定した。別の起動で動物対応版の通常画面を撮影し、白壁の影の縁に沿う214走査線では、最大の隣接輝度差が平均14.94→3.31階調になった。2回の起動で使った動物対応版のSHA-256は `231e3b92831701eea5d7129c65904a63302467b2dc3534a3ffc863c9d6c368ef`。[フレーム間隔](../2026-11-23-torch-density/gp-density-placed-hull-animal-ordinary/summary.json)・[通常画面の輝度差](animal-ordinary-display.json)・[4場面の通常画面](animal-ordinary/complete.json)

同じ1440p、12チャンク、白樺林・松明4本でGPUタイムスタンプを無効にして計測した。修正版は148フレームで平均67.62 ms・P99 72.66 ms、続けて測った従来キャッシュ版は153フレームで平均65.77 ms・P99 68.76 ms。順序を固定した1組の結果である。反射計算の実行順だけを変えた過去の約4 ms短縮とは異なる比較。火を部分的に隠す場面の画質を優先した。[今回の通常描画](../2026-11-23-torch-density/gp-density-placed-hull-ordinary/summary.json)・[同一条件の対照](../2026-11-23-torch-density/gp-density-placed-hull-control/summary.json)

形状記録用のR32F画像は12 MiB増えた。松明4本の検証済み区間で各12回NVIDIAドライバーに照会すると、MinecraftのJavaプロセスは以前の1,598～1,610 MiBから1,610～1,622 MiBになった。[時刻・PID・GPU全体を含む採取記録](residency.json)

ビルドは `python3 tools/build.py --placed-penumbra-study`。通常描画のZIPのSHA-256は `b224ea6f9424ad7dd8424f2c192e1708f97f734a802870cea42ebb722dcb4c02`。通常Labの設定・既存セーブは元のままで、すべての実機計測は専用コピーで行った。初回の診断用ZIPでは変数名の重複でIrisのリンクに失敗した。修正した診断版で撮影した画像だけを集計した。[初回のログ](grove-meter/complete.json)・[修正後の記録](grove-meter-r2/complete.json)

別起動のGPUタイムスタンプでは白樺林4本・148フレームのGPU時間が平均61.73 ms、手前の地形に照明を加えるパスが16.39 msだった。区画の変更検出は0.009 ms、形状記録の更新判定を含むパスは0.010 msだった。落ち着いた場面での値であり、森の伐採中の最大更新時間は未測定。今回の計測で使ったプロファイラはAqualumenのOpenGLタイムスタンプModである。ShellCheck 0.9.0で起動スクリプトを検査した。apitrace 11.1で既存の `eye.trace` から画素読み出し呼び出しを再確認し、Nsight Systems 2026.5.2の既存のスモーク試験はSQLiteで81件のOpenGLイベントを確認した。今回のMinecraftの収録にNsightは使用していない。[GPUプロファイル](../2026-11-23-torch-density/gp-density-placed-hull-gpu/summary.json)・[同一性と通常Labの復帰確認](verification.json)

## 自然の白樺まで歩いた記録

シード308060のサバイバルセーブのコピーを、石の野営地から再開した。実際の移動・アイテム操作で白樺の横の草地に松明を置き、幹の裏へ歩いて回った。既存のワールドアーカイブと元のLabを保全し、セーブを閉じてから白樺、設置した松明、野営地の壁掛け松明と青いランタンをブロック単位で確認した。追加区間は2,347ティック、徒歩20.60 m。重複を除いた3シードの合計は85,580ティック、3.5658日、950.08 mになった。[ゲーム内の3枚](survival-birch.jpg)・[到達時のセーブ](../../dist/Aqualumen-Birch-Torch-Walk.zip)・[経過台帳](playtime.json)

地形版の全プログラムをMesaでコンパイル・リンクした。RTXでもゲーム内のコンパイラと同じNVIDIA用ディレクティブを挿入した条件で、全プログラムがリンクした。素のNVIDIAドライバーにディレクティブを渡さない単体試験は182秒で止め、実ゲームの直列検証を再開した。この起動条件での全リンク完了時間は未確定である。[Mesa](compile-50_mesa.log)・[ゲーム相当のRTXコンパイル](compile-with-compiler-nvidia.log)・[単体試験の記録](raw-native-stop.json)
