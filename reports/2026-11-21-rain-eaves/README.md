# 軒先の石に映るランタン

同じ石床に暖色のランタンを映し、雨と光の経路を別々に切り替えた。開けた床に雨が当たると石の色が沈み、凹凸を残したまま照り返しが強くなる。ガラスの小屋根を架けると、その下の石にはランタンの拡散光が届き、雨による照り返しが消える。ランタンを回収した場合は、床が濡れたまま暖色の反射だけが消えた。

## 実ゲームで同じ石を追う

Minecraft 1.21.1、Iris 1.8.8、Sodium 0.6.9、RTX 3080 Ti を使用した。海洋バイオームの検証ワールドのコピーに石と滑らかな石を敷き、それぞれの列を同じ軒の内外にまたがらせた。屋根・灯り・視点はサーバー側でも照合した。以下は 1280×720 の診断描画で、同じ 11×11 画素に出た地面材質と光の内訳。反射の値はシェーダー内の相対輝度で、表示上の明るさやルクスとは単位が異なる。[全15場面と画素測定](material/take-4/measured.json) · [初期状態とカメラの投影](material/take-4/plan.json)

| 同じ石での操作 | ワールドの濡れ | 真上から雨が届く割合 | 表面の水膜の割合 | ランタンの鏡面反射 |
| --- | ---: | ---: | ---: | ---: |
| 降る前 | 0.000 | 1.000 | 0.000 | 0.000 |
| 降り始めから約25秒 | 0.929 | 1.000 | 0.780 | 0.138 |
| 頭上にガラスを置く | 0.969 | 0.000 | 0.000 | 0.000 |
| ガラスを石に替える | 0.984 | 0.000 | 0.000 | 0.000 |
| 小屋根を外す | 0.992 | 1.000 | 0.780 | 0.138 |
| ランタンを回収する | 0.996 | 1.000 | 0.780 | 0.000 |
| ランタンを戻す | ほぼ1 | 1.000 | 0.780 | 0.138 |
| 雨が止んで約80秒 | 0.075 | 1.000 | 0.000 | 0.000 |

ガラスを置いてもこの床のメッシュから受け取る天空光は 0.969 のままだった。空の明るさだけで濡れを決める方法ではこの屋根を見分けられない。ワールドの濡れが最終的な変化量の半分に達する時間は、実測の近似で降雨時 6.2 秒、乾燥時 21.1 秒だった。Iris 1.8.8 では乾燥用の定数を指定すると上昇側の設定が書き換わるため、製品コードは上昇だけを指定する。[時間曲線の元データと推定](material/wetness-fit.json) · [使用した Iris の該当箇所](material/iris-1.8.8-weather.txt)

## 光と材質の実装

各地形の上向きの面から、雨に触れる高さをカメラの周囲 256×256 ブロックに記録する。実際に描かれた石、ガラス、葉、水、部分ブロックを使う。屋根の高さと照明の遮蔽物は別々に評価し、個々のランタンについて拡散光と鏡面光には同じ遮蔽判定を使う。石、磨いた石、木、砂には異なる粗さと吸水時の散乱比を与えた。GGX 分布と Smith のマスキングを使い、光源の見かけの大きさを反射の幅に取り入れている。材質係数はバニラの見た目に合わせた近似値である。[地面の水膜](../../release/shaders/lib/rain_surface.glsl) · [濡れた物質の表面・内部のモデル](https://doi.org/10.2312/EGWR/EGWR99/273-282) · [PBRT のマイクロファセットモデル](https://pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory)

Photon の公開実装では降水、天空光、材質から水たまりを出す条件を参照した。Aqualumen は独自の屋根の高さ、近くの光源への光路、ゲームの時系列を使う。遠方では約96～124ブロックで天空光による雨よけの近似へ移る。バイオーム判定は視点側を使う。新たに屋根を架けた瞬間の床はすぐ乾いた外観に切り替わる。個々の石に残った雨水の履歴や、坂を伝う流れは今後の対象である。[Photon の雨の表面処理](https://github.com/sixthsurge/photon/blob/main/shaders/include/surface/rain_puddles.glsl) · [Iris の天候入力](https://shaders.properties/current/reference/uniforms/world/)

## GPU 検査

同じ RTX 3080 Ti の OpenGL 4.6 で水膜の光学・材質・局所光 51,793 項目、雨よけと共有画像 102 項目が通った。別実装の数値積分、ランタンの遮蔽、反射の相反性を含む。意図的に処理を変えた 23 通りの負の対照はすべて検出した。Iris のカスタム画像16枚の上限に収めるため、雨よけには毎フレーム消去する既存画像の 1～128 行を使い、生き物の影は従来の 0 行を使う。両端の雨よけセルを書いた後に 0 行の512要素も照合した。[通常版 GPU 検査](native-final.log) · [水膜の詳細](optics/gpu-film-final.json) · [負の対照](optics/mutants-2026-11-21.json)

## 雨粒にもランタンの色が届く

これまでの降水は、地面のブロック光に応じて空中の雨筋まで一律に橙色にしていた。1.7.0 では、雨粒の位置から設置光源・手に持った灯りまでの距離を求め、その光路を地形や色ガラスが遮るか評価する。粒に当たった光がどちらに散るかは、雨と雪に異なる角度分布を与えて近似した。濡れた石の照り返しには面の傾きと粗さ、空中の粒には光源・粒・目がなす角を使う。[降水の照明](../../release/shaders/lib/weather_light.glsl) · [散乱の角度分布の参考](https://pbr-book.org/4ed/Volume_Scattering/Phase_Functions)

同じ軒先でランタンを回収し、魂のランタンに替え、元のランタンを戻した。通常描画を各4秒、32コマずつ収録した。暗い空を背景にした雨筋では、明るくなった画素のRGB増分が旧処理の魂のランタンで **38 / 26 / 15**、新版で **8 / 28 / 37** となり、青い照明と整合した。新版の通常ランタンでは **50 / 32 / 16**、再設置後は **50 / 32 / 18**。この値は各画素と自身の時間中央値の差で、元画像の露出や雨粒の位置も影響する。消灯時には、その領域でいずれかのチャンネルが10階調を超えて明るくなる画素は約0.3%だった。[6枚の通常描画](material/rain-lights.jpg) · [点灯・消灯・魂のランタンを並べた12秒の動画](material/rain-lights.mp4) · [変更前](material/take-8/streaks.json) · [変更後](material/take-9/streaks.json)

Claude Sonnet が書いた降水処理を、配布版の既存の光源・遮蔽計算に接続した。実 GPU の独立検査で、距離減衰、暖色と寒色、石壁、色ガラス、手持ち、散乱角、太陽と局所光の独立を含む30項目が通った。12種類の意図的な誤実装も全て検出した。映像の左上や右端を通る筋は視点の手前にも描かれるので、1枚の写真から個々の雨粒の三次元位置は決められない。[実GPUの数値](weather-light/evidence.json) · [負の対照](weather-light/mutation.json)

石の比較画像の上段は1.6.0、下段は降水照明を差し替える直前の候補である。軒先の鏡面反射と雨よけは配布版にも同じコードを収録した。照り返しの中心を外れた滑らかな石の列では、軒の外／内の表示輝度比が乾燥時0.988、降雨時0.846、乾燥後0.988に戻った。光源が映る石が明るくなる一方で、その周辺の濡れた石の地色が沈む様子を、同じ視点と材質で追える。[旧版と候補の比較](fixture/eaves-comparison.jpg) · [床の画素位置](fixture/pose-a-patches.jpg) · [同じ石の表示輝度](fixture/results.json)

## RTX 3080 Ti でのフレーム時間

2560×1440・描画12チャンクの同じ軒先で、配布版とバイト単位で同一の候補を使った。カメラを固定し、各状態で遷移後の約10秒を採った。

| 状態 | 平均FPS | 99パーセンタイルのフレーム時間 |
| --- | ---: | ---: |
| 乾燥・ランタン点灯 | 50.5 | 22.56 ms |
| 雨・ランタン点灯 | 42.7 | 25.50 ms |
| 雨・ランタン撤去 | 62.8 | 18.07 ms |

計測専用ModはワールドIDを照合したコピーだけで有効にした。これらはこの画角と照明条件での Minecraft の実測値である。雨粒の光源処理を差し替える前の同じ雨・点灯区間は45.7 FPSだった。[配布版のフレーム間隔](material/take-10/client-frames.csv) · [区間別の集計](material/take-10/complete.json) · [変更前の同条件](material/take-5/complete.json)

## 雨上がりの太陽と石壁

滑らかな石を同じ位置から見ると、雨が降り切った状態では水膜が0.91まで育ち、太陽からの直接の照り返しはゼロだった。最初の撮影は雨のまま石壁を立てたため、雲の影と石壁の影を識別できなかった。再撮影では雲が晴れてから地面の**西側**に壁を出し、真上からの雨の通り道を空けた。太陽による鏡面反射の相対輝度は壁を置く前に7.43、壁を置くと0.00、撤去後に1.55だった。撤去後も自然乾燥が進み、水膜の量は時間とともに減少した。視点を横へ移すと0.007、元の向きへ戻すと0.42になった。この一連の測定ではランタンを外してある。[条件を切り分けた再撮影](material/take-11/measured.json) · [初回の記録](material/take-7/measured.json)

配布版の全プログラムと既存の光・水の回帰検査を実際の NVIDIA で再実行した。雨よけは102項目、雨粒の照明は30項目を通過した。配布 ZIP の SHA-256 は `eb760f429d32ea03b87d500a5f7d613a1d9a611794e3b2ddb6dd297ec80d4ec8`。[最終ビルドの GPU ログ](gpu-release-final.log) · [雨よけ](shelter/release-1.7.0.json) · [雨粒の照明](weather-light/release-native.json)

## 空を背景にした雨筋の距離

レビューで指摘された右上の雨筋について、同じ実ゲームの各粒から、光源までの距離・視点までの距離・位相角・実際の局所照明を同じフラグメントで取得した。診断描画の3区画は同じ座標の別々の量を表示する。粒が重なったところでは最後に描画された粒だけを読める。カメラと粒の距離から独立に3D座標も復元した。

最初の軒先の視点では、右上の直接光が明るい上位10%の雨筋は、通常ランタンから中央50%点で **3.76ブロック**、中央80%が **3.51～4.52ブロック**の範囲だった。背景の空と雨粒の位置には大きな隔たりがある。画面全体で、光源から0～3・3～6・6～9・9～12ブロックの各帯に落ちた雨粒の直接光の中央値は、それぞれ0.158・0.041・0.024・0.010まで減った。この位置では14ブロックより外の粒を取得できず、初回の範囲打ち切り検査は判定対象を欠いた。[近い視点の全測定](material/take-12/particle-depth.json) · [指摘があった通常画面](material/rain-lights.jpg)

## 遊べるワールドで一日を歩く

配布するサバイバルのセーブのコピーで、松明のあるオーク、坑道、池、軒先を19往復した。ゲームの保存統計は徒歩3,334.82 m、松明の採掘2回・再設置2回。出発時は時刻10000で雨、帰着時は35199で晴れ。実時間20分51秒の連続録画を保存した。チート無効・ピースフル、通常の3つのModを使い、テスト用Modも移動コマンドも使用していない。ワールドはこの検証用に設計した散歩道である。[雨の散歩道のZIP](../../dist/Aqualumen-Rain-Walk.zip) · [約30秒の抜粋](journey/run-7/walk-highlights.mp4) · [全編](journey/run-7/ordinary-walk.mkv) · [ゲームの保存結果](journey/run-7/complete.json)

同じ幹に付けた松明を外すと、その木の幹と真下の芝から暖色が消え、付け直すと元に戻った。晴れた昼の幹は消灯時の4.84倍、芝は2.05倍の表示輝度で、奥の白樺は1.00倍。手前の芝に樹冠が落とす日の影の輪郭は見えている。歩行映像は1600×900で描画し、960×540・12 fpsで記録した。出発から約3分46秒以降にF3表示から読み取れた232回の瞬間表示は36～60 fps、中央値49 fps。F3を表示する地点に偏るので、1440pのフレーム時間は上の専用計測を参照されたい。[雨と晴れの点灯・消灯・再設置](journey/run-7/oak-torch.jpg) · [画面座標と測定値](journey/run-7/torch-pixels.json) · [F3の観測記録](journey/run-7/displayed-fps.jsonl) · [散歩道の検証方法](journey/README.md)

もう一つのカメラをランタンから約21ブロック離すと、通常ランタンから14ブロックより遠い雨粒を211万サンプル以上取得できた。暖色・魂・暖色再設置のいずれも、その範囲におけるランタンの直接寄与は測定の分解能内でゼロだった。カメラ位置の検算には Minecraft が保存したプレイヤー座標を使った。遠い方の最初の照合は、整数の水平座標を指定したテレポートがブロックの中央に着くため、想定した位置が0.5ブロックずれていた。セーブにある実座標で再計算した結果、視線から復元した光源距離とシェーダーの値との99パーセンタイル誤差はどちらの視点も0.11ブロック未満だった。[2視点の測定](material/particle-distances.json) · [ゲームが保存したカメラ位置](material/take-13/saved-particle-camera.json)

## 幹の松明と手持ちの魂のランタン

同じ木に同じ向きで立ち、通常のサバイバル操作で、両方消灯・松明だけ・魂のランタンだけ・両方点灯の4状態を撮った。松明だけなら樹皮は橙色、魂のランタンだけなら草と樹皮に青緑の光が届く。両方を点けてから松明を回収すると、幹に冷たい色が残る。再設置後も両方の寄与が戻った。炎を避けた同じ樹皮の表示色RGB中央値は、両方消灯が (58,45,28)、松明だけが (186,106,44)、魂だけが (68,83,57)、両方が (187,117,57) だった。[同じ木での4状態](journey/run-8/two-lights.jpg) · [光源ごとの比較と再設置](journey/run-8/two-lights.json) · [約65秒の一連の操作](journey/run-8/ordinary-walk.mkv)
