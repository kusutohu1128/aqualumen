# 赤い窓越しに見る灯り

Aqualumenの色付き板ガラスは、松明と太陽から届く光に厚み依存のRGB吸収を使っていた。カメラからは、従来は色付きの面をアルファ合成していた。今回の試作では、視線が柱と接続部分の中を実際に通った長さから、背後の物から目に届く光の量を計算する。柱と腕が重なる部分は一度だけ数える。赤板を斜めに見れば吸収が増え、板の中から見れば眼前に残った厚みだけが効く。染料ごとの係数はゲーム向けの近似。[透過率の式](https://www.pbr-book.org/4ed/Volume_Scattering/Transmittance)

## Minecraftで測った背景光

RTX 3080 Ti、Minecraft 1.21.1、Iris 1.8.8、Sodium 0.6.9、1280×720。専用の計測パックで不透明背景の線形RGBを隣り合う列で0.75と0.25に固定し、ガラスの実描画を通った後に読み出した。最終出力は8ビットで、露出・トーンマッピング・大気は計測時にバイパスした。画面中央の照準を避けた128画素対で、隣り合う画素の差から各色の透過率を求めた。表は中央値。シェーダーと比較用計算は別に実装した。[測定器と場面](room.py)・[読出しと計算値](readout.py)・[全10条件の結果](transmission.json)

| --- | ---: | ---: | ---: |
| 変更前・赤板1枚 | 0.604 | 0.604 | 0.604 |
| 候補・赤板1枚 | 0.980 | 0.816 | 0.792 |
| 候補・赤板2枚 | 0.965 | 0.667 | 0.635 |
| 候補・赤と青を1枚ずつ、どちらの順序でも | 0.792 | 0.722 | 0.776 |
| 候補・赤板を30度斜めから | 0.980 | 0.792 | 0.769 |
| 候補・赤板の中央から外を見る | 0.988 | 0.902 | 0.894 |
| 候補・光るブロックが赤板より手前 | 0.996 | 0.996 | 0.996 |

板のないときの読出しは全色0.996。10条件で中央値と理論値の差は最大0.0047。この数値の対象は中央の測定領域。ガラス模様に元々ある高いアルファは表面の模様として描くため、その部分の応答は中央の平らな部分と異なる。Fableからの提案をもとに、同色の積層、異なる色の順序、眼が板の内部にある場合を分けた。[助言原文](advisor.txt)

## 適用範囲

対象は近くの色付き**板**ガラス16色。実機の数値検査では赤・青を使った。カメラ周辺の格子へ取り込んだ板を使い、格子の各軸で眼から18〜23ブロックの間は従来の描画へ滑らかに戻す。立方体ガラスは通常のアルファ合成で描く。透明物の寄与には眼からその物までの光路を使い、水の反射・屈折に使う不透明背景は着色前のものを保持する。粗い水面の臨界角付近で複数方向を積分する空の近似など、すべての二次光路での色の一致は未検証。

候補は `python3 tools/build.py --camera-glass` で生成する。SHA-256 は `2635806ad54b0a99e645b62d01a71d4cb310c63b4429778eaf217d1a54743dd3`。45プログラムをRTXとMesa llvmpipeでコンパイル・リンクした。隔離クライアントには既存の照明コンパイラ0.3.0を使用した。[候補ZIP](../../dist/Aqualumen-Camera-Glass.zip)・[コンパイラ](../../dist/aqualumen-lighting-compiler-0.3.0.jar)・[NVIDIA](compile-nvidia.txt)・[Mesa](compile-mesa.txt)

## 通常画面と水の前後関係

同じカメラでシーランタンを撮った。通常表示の赤板1枚では、光源の中央が従来版より少し暖かく明るく見える。赤と青を重ねた画像の細い青い帯は、奥の青い板が壁へ直角につながる箇所。そこでは厚みが1/8から9/16ブロックに増える。帯の内側24画素対で、赤・青を入れ替えた両方の測定値が各色の理論値から0.008以内に収まった。画像はゲームのF2キャプチャの同じ座標を切り出したもの。[通常画面の比較](windows.png)・[接続部分の測定](junction.json)

水面を見下ろした別の部屋では、水面自体が発する校正信号が眼に届く割合を調べた。47度下を向いたとき、赤板が眼と水面の間にあればRGBは0.969、0.745、0.714。板を水槽の向こう側へ移すと全色0.996になった。[水面の校正](water-surface.json)

さらに水槽の中に、水を含む赤い板ガラスを設置した。実際の屈折計算で確定した水底の位置に対し、水面から水底までの線分がガラスの各直方体を通る長さを独立に計算した。水面より奥の板は、水面から眼までの区間にはかからない。同じピクセルの水底から水面までの区間では吸収が生じる。中心付近の2,688画素中、独立計算の緑チャンネルが230/255を下回る1,702画素で比較し、中央値は実装・予測とも174/255、最大差は1/255だった。板を外した後は2,688画素すべて255/255に戻った。この検査は水底の確定した屈折光路を対象とする。[水中の試験条件](submerged.py)・[水底の結果](submerged-transmission.json)

## 1440pの描画負荷

最初の候補では不透明面の照明シェーダー内で視線の吸収を計算した。そのため板がない部屋も重くなった。2番目の候補は、地形照明が終わった後で、未着色の不透明背景を専用の全画面パスで読み、眼までの吸収を一度だけ適用する。透明物の光と水面の二次光路には最初の候補と同じ実装を使う。

RTX 3080 Ti、2560×1440・12チャンクで同じステージ定義とカメラを使用。GPUタイムスタンプを切ったMinecraftの平均フレーム間隔。旧版は既存の測定を引き継いだ。

| 場面 | 変更前 | 照明内で吸収を計算 | 吸収を別パスで計算 |
| --- | ---: | ---: | ---: |
| 板のない部屋 | 27.15 ms | 33.77 ms | 27.20 ms |
| 松明と赤板の部屋 | 44.64 ms | 50.42 ms | 43.76 ms |

別パスの測定フレーム数は順に368、229、99パーセンタイルは29.96 ms、46.31 ms。2場面とも最初の候補から約6.6 ms短縮した。変更前との差は各1 ms未満で、この測定から恒常的な優劣は判断しない。[変更前の記録](../2026-11-23-screen-windows/screen-room/summary.json)・[最初の候補](frames-1440/summary.json)・[別パス版](pass-frames/summary.json)

配布候補には **Glass-View-Pass** を選んだ。最初の候補と別パス版を1280×720の10条件で照合し、校正画像計9,216,000画素の差は0だった。通常表示では最初に撮った板なしの部屋に最大4/255の差があったため、最終露出だけを固定して、板なし・赤板1枚を再撮影した。両場面とも全画素が一致した。通常露出の赤1枚、赤青、手前に光源がある場合では差は最大1/255。[比較データ](decision.json)・[露出を固定した通常表示](fixed-display.json)

最終版は `python3 tools/build.py --glass-view-pass` で生成できる。SHA-256 は `0309eb7c180e1e4d27977463c438ab3fe135b2f5054a2c263eb6ca245de2b293`。全46プログラムを両ドライバでコンパイル・リンクした。水と雨、太陽と視線の透過関数は最初の候補と同じソースを収録している。各クライアントの隔離・終了後に確認した通常Labの選択は Aqualumen 1.8.0、物理Modは0.2.0。[最終版ZIP](../../dist/Aqualumen-Glass-View-Pass.zip)・[NVIDIA](view-pass/compile-nvidia.txt)・[Mesa](view-pass/compile-mesa.txt)・[通常Labの照合](pass-room/preflight.json)

Fableは次の優先事項に、夜間の屋外で松明と降雪が重なったときの滑らかさを挙げた。白樺林の松明4本の以前の測定値と、雪村でのF3の瞬間表示は別の条件で得た。原因を特定するには同じ座標と時刻で松明の本数と降雪を別々に変える必要がある。[方向性の助言](advisor-direction.txt)

## 雪村のサバイバル

前回の赤い窓がある家から通常操作で再開した。低いポーチのランタンへ照準を向けると手前の窓台に当たった。街路に吊った別のランタンはポーチから直接狙えて、家に戻って赤い板を狙った画面にも、雪の段の上、窓の左寄りに写った。最終画面の照準位置は板の中央。保存されたワールドの街灯位置は `(-896,72,571)`、ガラスは `(-901,71,576)`。[ポーチから見た街路のランタン](../2026-11-22-ceiling-return/village/east-stair-window/street-lamp-from-outside-ingame.png)・[赤い窓から見た街路](../2026-11-22-ceiling-return/village/street-window-home/the-street-through-the-red-window-ingame.png)

ドアと窓台に視線を遮られた回、戸口からポーチへ出た回、階段や開いたドアの端で歩行が止まった回も保存した。そのたびに直前の保存位置から再開した。東側の半段を上り、開いたドアの幅に合わせて西へ寄ってから入室。元のワールドから時刻・位置・歩行統計の連続性を照合した。ティック70,284から77,609までの7,325ティックを加え、全3シードの実プレイは144,009ティック、約6.00ゲーム日。最終セーブの赤い板は13枚、松明は30本。板と皮を剥いだトウヒの原木のスロットは入れ替わり、持ち物の種類別個数は一致した。[操作記録](../2026-11-22-ceiling-return/village/street-window-home/complete.json)・[セーブ検査](../2026-11-22-ceiling-return/village/street-window-home/save.json)・[累計](playtime.json)・[遊べるセーブ](../../dist/Aqualumen-Porch-Window.zip)
