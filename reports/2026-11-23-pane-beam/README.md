# 松明が色ガラスの窓を照らす夜

Minecraft Java 1.21.1、Iris 1.8.8、Sodium 0.6.9で、松明1本と白い壁の間にある板ガラスを組み替えた。日光と松明に対応する前版では、RTX 3080 Ti・2560×1440・12チャンクで、板なしの平均フレーム間隔は27.10 ms、東西に並べた赤い板を通すと62.34 msだった。[前版の配布パックと試験](../2026-11-23-stained-panes/README.md)・[元のフレーム間隔](../2026-11-23-stained-panes/timing-sun-at-night/summary.json)

## 二つの試作

最初の試作は、受光点から炎の円盤に届きうる範囲を画素ごとに調べる。染料が同じで、つながった中心柱と腕が長方形の板を隙間なく満たす場合に、その箱を通る距離を炎の24点分求める。隙間や曲がり角をまたぐ経路には元の追跡が使える。判定はブロックの1/16を単位とする整数の体積で行う。[交差長の実装](../../release/pane-beam/shaders/lib/pane_beam.glsl)

二つ目の試作は、設置松明と受光側の1ブロック区画の組ごとに、区画全体から見える板の外形を先に求める。色、接続形状、ブロック、松明の変更を検出して更新する。各画素では保存した外形を使い、実際の受光位置から火に届く光の色を計算する。動物が光を遮り得るときは元の光線計算を通る。追加のテクスチャ領域は512×512個のR32Fで1 MiB。外形の記録には既存の二つの格納先を再利用する。[外形の判定](../../release/window-cells/shaders/lib/window_cells.glsl)・[炎の積分](../../release/window-cells/shaders/lib/window_disk.glsl)

最初の実ゲーム計測では、一つ目の試作の平均フレーム間隔は赤窓で58.69 ms、板なしで33.66 msだった。計測用GPUタイムスタンプを外した連続フレームの値。赤窓について3.65 msの短縮、板なしについて6.56 msの増加を観測した。[最初の試作の結果](candidate-night/summary.json)

## 測定方法

夜の白壁は、実ゲームのF2画像から受光点のワールド座標とRGB各8ビットの透過率を読み取る。座標の一致した点どうしを比較する。実験用パックは通常版の光源計算を通り、結果と選んだ経路を計測画像に書く。別の参照として、Minecraftクライアントのモデルから作った柱・腕に、各地点から1,536本の光線を当てる。固定視点の通常場面には前版の撮影結果を使い、窓の隙間、石、牛、位置を左右3 cmずらした視点には追加の比較元を撮影する。[画面の読み取り](verify.py)・[独立した参照積分](../2026-11-23-stained-panes/reference.cpp)

すべての実験は隔離したゲームディレクトリで順に実行する。各ランの開始・終了時に元のLabの設定・Modと保存元を確認する。通常表示と計測表示のSHA-256を別々に記録する。[実行条件と試験場面](window_room.py)・[パックのSHA-256](beam_versions.py)・[Fableの初回助言](advisor.txt)・[フレーム時間を提示した後の助言](advisor-followup.txt)

最初の試作では14場面、延べ205,232組の白壁の受光点を元の光源計算と照合した。差の出たのは4組で、いずれも最大1階調。赤い窓のある壁で、さらに石を置いて暗くなった10,216地点と、牛が光を遮って暗くなった11,216地点は元版と一致した。これらの地点では元の追跡処理が選ばれていた。赤窓で着色される地点の、1,536本の参照積分に対する最大チャンネル誤差のP95は0.92階調だった。[照合結果](comparison.json)

条件の順を逆にした測定でも、赤い窓で元版62.90 ms、画素ごとに外形を調べる試作58.78 ms。板なしでは26.49 msから33.16 msへ伸びた。窓を置かない場面でも繰り返し負荷が増えたため、この一つ目の試作の通常採用は見送った。[逆順の元版](control-reverse/summary.json)・[逆順の試作](candidate-reverse/summary.json)

## 雪村の朝

前回保存した赤い窓の家を「日光と松明」版で開き、玄関を出て外壁に暖色の松明を掛け、室内に戻った。セーブ上で北向きの壁松明、赤窓、作業台、既存の二つの玄関ランタンと室内の魂の松明を確認した。手持ちの松明は32本から31本になった。歩行11.54 m、時刻47,588から50,131ティック。3シードの継続は累計4.85546ゲーム日・1,177.61 m。村では日の出と目の順応も進む。光量の数値比較には別の固定部屋を使った。[外と内から見た窓](village.jpg)・[続きから遊べるセーブ](../../dist/Aqualumen-Lit-Red-Window.zip)・[経過の内訳](playtime.json)

## 編集をまたぐ記録

外形を保存する試作について、実際の計算シェーダー二つに対し、同じ格子に15回続けて入力を与えた。赤から青への染め替えと、染料を保ったままでの板の接続変更は、ともに変更を与えた回に外形の記録が切り替わった。消灯中の記録は読み手のない領域に残る。再点灯した回には、消灯中に替えた青が選ばれた。RTX 3080 TiとMesa llvmpipeの両方で確認した。MesaでのOpenGL呼び出しをapitraceに保存し、31回の計算ディスパッチ、50回の中間テクスチャ読み出しを照合した。[RTX](edits-nvidia.txt)・[Mesa](edits-mesa.txt)・[トレースの照合](edit-trace.json)

画素ごとに外形を求める一つ目の試作にも、正逆両方向の斜め光線、細い柱、隙間、石、複数色を含む入力を与えた。各ドライバで10,272組のうち2,611組が外形の条件を満たした。対象の24点に対して各モデル部品を個別に積分した倍精度計算との差は、RTXで最大0.00000072、Mesaで最大0.00000031のRGB透過率だった。[入力とGPU別の結果](synthetic.json)

## 木陰で幹を壊し、牛が横切るとき

通常表示のF2画像でも、板や幹を透かして見ている画素を除き、同じ草の位置を比較した。幹の影に入る952地点では、松明を置くと画面輝度が中央値29.26階調上がり、幹を置くと11.92階調下がり、幹を壊すと11.99階調上がった。消灯後と初期の差は中央値0.07階調。比較元と外形を保存する版の中央値は、この952地点で一致した。画面輝度は表示RGBに0.2126、0.7152、0.0722の重みを掛けた0〜255の値。[木陰と松明の4枚の実画面](grass.jpg)・[草と白壁の数値](grass-display.json)

白樺の葉の下に赤い板、松明、幹を置き、同じフレームで保存した窓の記録を使う光と、元の追跡による光のRGB透過率を読んだ。幹を置いて赤チャンネルが180超から32未満になった草の1,407地点、白壁の10,220地点は、幹を壊した後に全地点で180超に戻った。

松明の設置、幹の設置、幹の撤去、松明の撤去の前後をそれぞれ12 Hzで5秒記録した。四つの動画とも60フレームすべてが校正を通り、草と壁で同時に読めた両方式のRGBの最大差は0階調。消灯の動画では、松明の寄与を読める地点が46,155から0になった。編集と次の撮影の間に表示されたフレームの状態は、この動画からは決まらない。

牛は5.40 m歩いた。132フレーム中、異なる照明分布は76枚。位置の一致する壁・床で前の分布から6階調を超えて変化した延べ88,404地点も含め、二方式のRGBは一致した。[草・白壁と編集動画の集計](grove.json)・[牛が横切る計測動画](grove-edits/cow-motion.mp4)・[松明を外す計測動画](grove-edits/extinguishing.mp4)

## 通常表示のフレーム間隔

RTX 3080 Ti、2560×1440、12チャンク、夜の松明1本。表の2値は、板なし→赤窓の順と、その逆順での平均フレーム間隔（ms）。各値はGPUタイムスタンプを無効にした実ゲームのおよそ10秒間。

| 場面 | 元版 | 画素ごとに外形を探索 | 外形をVRAMに保存 |
| --- | ---: | ---: | ---: |
| 板なし | 27.10 / 26.49 | 33.66 / 33.16 | 33.24 / 32.69 |
| 東西に並べた赤窓 | 62.34 / 62.90 | 58.69 / 58.78 | 47.15 / 47.84 |

窓の外形を保存すると、赤窓のP99は元版64.94 / 66.79 msから49.92 / 50.45 msに下がった。一方、板のない部屋は平均が6.14 / 6.20 ms伸びた。14場面の白壁で延べ205,231組の受光点を照合すると、2組で1階調差が出た。赤だけ・青だけ・複数色を重ねた固定視点の窓は、元版と同じ8ビットRGBだった。[順方向の計測](cells-night/summary.json)・[逆順の計測](cells-reverse/summary.json)・[全受光点の照合](cells-comparison.json)

窓のない自然生成の白樺林でも、同じ二つの通常版を別々に起動した。松明なしでは元版40.00 ms、外形を保存する版40.80 ms。松明4本では83.82 msから109.73 msへ伸びた。白樺林は各版1起動。窓のある部屋で速く、複数の松明で林を照らすと遅いため、外形を保存する版も比較用の実験版とした。[白樺林の元版](birch-control/summary.json)・[外形を保存する版](birch-cells/summary.json)

## パックと計測環境

実験用の通常表示ZIPは `python3 tools/build.py --window-cells`、最初の比較版は `python3 tools/build.py --pane-beam` で再現できる。再ビルドした両ZIPのSHA-256はゲームで使ったものと一致した。RTXとMesaで各版37プログラムのコンパイル・リンクを確認した。実MinecraftではLighting Compiler 0.3.0を隔離インスタンスで使用した。[外形を保存する試作](../../dist/Aqualumen-Window-Cells.zip)・[元の「日光と松明」版](../../dist/Aqualumen-Sunlit-Panes.zip)・[RTXコンパイル](cells-compile/compile-nvidia.txt)・[Mesaコンパイル](cells-compile/compile-mesa.txt)

ShellCheck 0.9.0でGPUプロファイラのビルドスクリプトを検査し、指摘は0件だった。apitrace 11.1で今回の編集試験を記録した。Nsight Systems 2026.5.2については過去に取得したMinecraftのSQLiteを読み取り専用で再確認し、OpenGL APIイベント35,662件を確認した。今回のフレーム間隔とGPU区間の計測には、隔離インスタンスのゲーム内プロファイラを使用した。[Nsightの過去の実機収録](../2026-11-23-torch-brick-scan/nsight-minecraft.json)

## GPU時間が変わった描画パス

別の起動でGPUタイムスタンプを有効にして比較した。下表の単位はms。各パスを含む親区間と子区間は重なる。

| 平均GPU時間 | 元版 | 外形を保存する版 |
| --- | ---: | ---: |
| 板なしの部屋の deferred 全画面描画 | 9.56 | 15.31 |
| 赤窓の部屋の deferred 全画面描画 | 40.16 | 25.84 |
| 白樺林・松明4本の deferred 全画面描画 | 36.93 | 62.60 |
| 同じ白樺林の shadowcomp 区間 | 12.98 | 12.99 |
| 同じ白樺林のGPUフレーム全体 | 79.21 | 104.91 |

白樺林4本のGPUフレーム差25.70 msのうち、同じフレームで測った deferred の差は25.67 ms。どちらの配布用ZIPも同じドライバで計測した。通常のフレーム間隔を測った起動とは別のデータである。[板なしと赤窓の元版](gp-window-control-profile/summary.json)・[赤窓の試作](gp-window-cells-profile/summary.json)・[林の元版](gp-window-birch-control-profile/summary.json)・[林の試作](gp-window-birch-cells-profile/summary.json)

最初のGPUタイムスタンプ起動 `cells-profile` はプライベート用のラン名が `gp-` で始まらず、プロファイラ自身が有効化を拒否した。集計には正常起動した `gp-window-*` のみを使用した。光の記録を更新する二つの計算パスについても全採用フレームで呼び出しを確認した。[パック・計測値・Labの照合](audit.json)

Fableが提案した対照として、光源・外形の更新と積分を残し、窓専用の二つのテクスチャ読み出しだけを実行時の一様変数に置き換え、板のない部屋で計測した。各版の先頭299フレームでそろえると、deferred は元版9.570 ms、外形を保存する版15.307 ms、読み出しを差し替えた版15.304 ms。差し替えによる回復は0.002 msで、回帰した5.737 msを説明できなかった。通常の照明パスに窓専用コードを組み込むことの影響が、次に切り分ける対象になる。GPUのレジスタ使用量や実際に発行された命令数はここでは測っていない。[299フレームの対照](uniform-lookup.json)・[変更した読み出し](lookup_probe.py)・[Fableの助言](advisor-profile-answer.txt)
