# 色付き板ガラスを通る松明の光

赤い板の向こうの白壁に、松明の光が淡く赤く落ちる。板を縦に長く通ると色が濃くなり、ガラスのすぐ脇を抜けた光には色が付かない。Minecraft 1.21.1、Iris 1.8.8、RTX 3080 Tiで隔離した夜の部屋を作り、松明・壁・カメラを固定して板を組み替えた。[通常表示の比較写真](room.jpg)・[インストール用ZIP](../../dist/Aqualumen-Stained-Panes.zip)

## 白壁に届いた光

MinecraftのクライアントJARにある板ガラスのモデルから、中心柱と回転した接続部分を読み取った。同じ壁面の3,681地点から円盤状の火へ各1,536本の光線を引き、独立に求めたRGB透過率と実ゲームの計測用パックの出力を比較した。表は、参照で最小チャンネルの透過率が98.5%を下回った地点での、3チャンネルのうち最も大きい絶対誤差。単位は255分の1。[CPU参照](reference.cpp)・[新旧の比較元](control-score.json)・[全条件の集計](pane-score.json)

| 火と壁の間にあるもの | 着色された地点 | 旧版の誤差 P95 | 試作の誤差 P95 |
| --- | ---: | ---: | ---: |
| 赤い板が1枚、接続なし | 401 | 50.01 | 1.14 |
| 東西につないだ赤い板 | 3,159 | 71.04 | 0.92 |
| 東西につないだ青い板 | 3,156 | 未計測 | 0.73 |
| 南北につないだ赤い板 | 2,383 | 未計測 | 0.70 |
| 赤いL字の角 | 3,210 | 未計測 | 0.74 |
| 赤と青を重ねた2列 | 3,381 | 未計測 | 1.98 |
| 厚さ1ブロックの赤いガラス | 3,681 | 0.61 | 0.61 |

赤と青を重ねた場合の最大誤差は9.38階調。板の境界にまたがる火の円盤を有限個のサンプルで積分するため、縁では誤差が大きくなる。すべての板を外した後の静止画では、全3,681地点が最初の空気の状態と同じRGB (255, 255, 255) に戻った。撤去直後から何フレームで戻るかは今回の測定範囲外。

通常表示のF2画像でも、カメラから板を透かして見てしまう位置を除いて、白壁を直接比較した。同じ10,421地点で、青い板を赤い板に替えた画素差の中央値はRGB (+4, −7, −8)。どちらの板にも火が遮られなかった796地点では (0, −1, −1) だった。各画像では目の順応が動くため、最終画素の明るさの変化には露出も含まれる。[表示画素の照合方法](display.py)・[集計](display.json)

## 板の形と透過の計算

厚さはブロックの2/16。中心柱と東西南北の接続を、16色それぞれでMinecraftのブロック状態から取得する。光線と実形状の交差長を求め、接続部分が中心柱と重なる距離を一度だけ数える。通過距離に合わせて、厚い色ガラスと同じ1ブロックあたりのRGB透過率を累乗する。色ごとの係数はゲーム向けの設定値。実在ガラスの分光測定値は使用していない。[板の交差計算](../../release/stained-panes/shaders/lib/pane_transmission.glsl)・[Beerの法則と透過率](https://pbr-book.org/4ed/Volume_Scattering/Transmittance)

松明の直接光、葉に届く光、拡散反射を追う光線に同じ板の形を用いた。白壁の測定対象は設置松明の直接光。日差しが窓を抜けて床に落とす色、移動する動物と板の縁が重なる場合、透過後に二回反射する色の個別精度は今後の検証対象。Devin経由のClaude Fable 5.2に、薄板の形、接合部の二重減衰、板を外したときの比較、直射日光との切り分けについて意見を求めた。[助言の原文](advisor.txt)

ビルドは `python3 tools/build.py --stained-panes`。配布ZIPのSHA-256は `7f5403e7c3fd57666f2417837bfe3d72d4d142d7b4cce29fdeff891504e36a77`。最初の試験に使った通常表示ZIPは別の圧縮設定で作成した。展開したファイルはすべて一致する。実Minecraftの1440p計測には配布ZIPを使った。

## フレーム間隔と実行環境

RTX 3080 Ti、2560×1440、描画距離12チャンク。同じ隔離ワールドに比較元と配布ZIPを順番に読み込み、各条件でスクリーンショット取得後に待ってから、連続する約10秒のMinecraftの描画フレーム間隔を集計した。VirtualGL経由。GPUタイムスタンプは無効。平均とP99はいずれもミリ秒。

| 同じ松明1本の部屋 | 比較元 平均 / P99 | 色付き板対応版 平均 / P99 |
| --- | ---: | ---: |
| 板を置かない | 26.37 / 30.33 | 26.76 / 29.12 |
| 赤い板を東西につないで置く | 26.22 / 29.19 | 60.74 / 63.67 |

赤い板のある場面で対応版は約16.5 fps相当。板を含む光路で火の面積を24点で追加評価する負荷があり、この部屋では重い。比較元は板越しの松明の光を着色していない。各版1起動ずつの測定で、板なしの0.39 ms差を一般的な速度差として解釈することはできない。[比較元の間隔](timing-control/summary.json)・[配布ZIPの間隔](timing-pane/summary.json)

ゲームモデルを使った単体検証では、16種類の接続、平行・接触・対角・逆向きを含む15,488本の光線について、ガラス内部の通過距離を比較した。実測した最大絶対誤差はRTXで1.42×10⁻⁷ブロック、Mesa llvmpipeで1.12×10⁻⁷ブロック。16色×16接続の256状態も照合した。Mesaでのapitraceには計算の実行と61,952バイトの読み戻しが記録されている。[NVIDIA](geometry-nvidia.json)・[Mesaとapitrace](geometry-mesa.json)

## 雪村の家に赤い窓を作る

通常のサバイバルセーブを再開し、雪原でポピーを一輪摘み、146.55 m歩いて家に戻った。ポピーから作った赤い染料で手持ちのガラス8個を染め、うち6個から板ガラス16枚をクラフト。以前開けた窓に1枚をはめた。完成したセーブには東西両側につながった赤い板、作業台、魂の松明、天井と玄関のランタンがあり、所持品に板15枚と染めたガラス2個が残る。3シードの連続したサバイバルの累計は4.7495ゲーム日、1,166.07 m。[窓の設置前後](village.jpg)・[ブロック状態](window.json)・[再開用セーブ](../../dist/Aqualumen-Red-Window.zip)・[プレイ記録](playtime.json)

初回の工作は、作業台のスロットと外枠を画面認識で取り違えて停止した。保存した画面で左右の外枠を識別できることを確認し、採取完了のセーブから工作を再現した。最初の工作分は累計時間に含めていない。元のLabは1.8.0 / physics 0.2.0で、テスト用のコンパイラModは隔離したMinecraftで有効にした。[照合結果](verification.json)

## 夕方、色窓を通って床に届く日光

雪村に窓をはめた後、隔離した白い部屋で夕方の太陽を出し、西側の壁と屋根を開けた。松明を外し、窓を開放・赤板・青板・石・再開放の順に替えて、同じカメラから床を撮影した。Claude Fableは、毎日使う家での次の検証として、ガラスを直接見ていない床に色が落ちるかを挙げた。[助言](advisor-followup.txt)・[固定した時刻と部屋](sun-window/geometry.json)

松明の透過に対応した段階では、ガラスを通る床3,173地点すべてで、赤い窓と青い窓の直射日光成分がビット単位で同一だった。通常表示でも、石の遮光対照が22階調以上暗くなった7,169地点で、赤板−青板の表示色差は中央値で (0, 0, −1) だった。[直射成分の旧版計測](sun-direct.json)・[通常表示の旧版計測](sun-display.json)

日光にも対応させた版は、当該フレームの板ガラスが入る8ブロック幅の区画を記録する。太陽に向かう線がこの区画に入ったときに実際の板の厚さを調べ、既存の直射光にRGB透過率を掛ける。元の地形や石による遮光も適用する。色を計算する範囲はカメラに近い板で、各軸のうち最も大きな距離が18から23ブロックの間で寄与を滑らかに減らす。色ガラスを照らす光のうち、ここで検証したのは晴天での直射日光。日陰の天空光、厚い色ガラスブロックの日光、複数回散乱はこの比較の対象外。[日光の光路計算](../../release/sunlit-panes/shaders/lib/sun_panes.glsl)

最終表示前の不透明地形の直射成分を保存したバッファ `colortex8` を、色と露出を変換する前に読み出した。世界座標に戻した床から、実ゲームの太陽方向に光線を伸ばし、ゲームモデル上で0.06ブロックを超える厚みを通る地点を選んだ。下表の3,173地点で通過距離の中央値は0.195ブロック。透過率は同じ床の開放時を基準にした。

| ガラス | モデルから求めた透過率 R / G / B | 実Minecraftの中央値 R / G / B | 最大チャンネル誤差のP95 |
| --- | --- | --- | ---: |
| 赤い板 | 96.88% / 73.05% / 69.94% | 97.30% / 73.34% / 70.25% | 0.50ポイント |
| 青い板 | 72.32% / 81.93% / 97.10% | 72.64% / 82.22% / 97.51% | 0.48ポイント |

同じ3,173地点で石に替えると全地点の直射成分がゼロになった。完全に素通りする光路24,682地点も別に集計した。最初の試行では起動時に単体コンパイラが重なったため、結果を除外し、コンパイル完了後に実Minecraftを起動し直した。各GPU実測に採用したランのプロセス監視に重複はない。[配布版の直射成分](sun-filtered-direct.json)・[除外した試行](sun-filtered-meter/preflight.json)・[採用した試行](sun-filtered-meter-r2/complete.json)

通常のF2写真では、太陽の光線が実際に板を通る3,173地点で、赤窓と青窓の画素差の中央値が (0, −1, −1) から (+16, −22, −38) に変わった。板の脇を光が素通りした24,682地点の中央値は (0, 0, 0)。厚さ1ブロックの石が落とす影は薄い板の影より広いため、石の影全体と、板を通った光の届く床は別々に集計している。写真の丸印はすべて同じ床の位置。[日光を受ける床の比較写真](sunlight.jpg)・[日光と松明に対応したZIP](../../dist/Aqualumen-Sunlit-Panes.zip)

今回の板形状の単体検証はapitraceで追い、フレーム間隔はゲーム側の連続フレーム計測で取得した。Nsight Systems 2026.5.2も起動でき、以前の実Minecraft収録のSQLiteを読み直すと、Java描画スレッドのOpenGL APIイベントは35,662件だった。板ガラスのフレーム間隔にはその過去の収録を混ぜていない。[以前のNsight収録](../2026-11-23-torch-brick-scan/nsight-minecraft.json)

### 配布用の「日光と松明」版のフレーム間隔

RTX 3080 Ti、2560×1440、12チャンク、各条件で連続する約10秒を測った。夕方の小部屋で赤窓を通して床を照らしたとき、松明の透過だけに対応する版は平均20.75 ms / P99 23.89 ms、直射日光にも対応する配布版は平均21.93 ms / P99 24.40 ms。開放時の平均はそれぞれ21.17 msと21.30 msだった。各版1起動、同じ順序での比較。[比較元](sun-timing-baseline/summary.json)・[配布版](sun-timing-filtered/summary.json)

インストール用ZIPは `python3 tools/build.py --sunlit-panes` で再生成できる。SHA-256は `c84ea61f7ae5cc97872edaf6789bc5541297f4a253f7465d6e16dbc51b60443f`。対応環境はMinecraft 1.21.1、Iris 1.8.8、Sodium 0.6.9。NVIDIAでの実ゲーム試験ではLighting Compiler 0.3.0を使用した。NVIDIAとMesaでそれぞれ37プログラムのコンパイル・リンクも確認した。[配布用ZIP](../../dist/Aqualumen-Sunlit-Panes.zip)・[コンパイル用Mod](../../dist/aqualumen-lighting-compiler-0.3.0.jar)

同じ配布ZIPで夜の松明1本の部屋も再確認した。板なしでは平均27.10 ms / P99 30.60 ms（369フレーム）、赤い板を並べると平均62.34 ms / P99 64.94 ms（161フレーム）。この条件で残る負荷は、板を通して松明の面光源を積分する場面に現れている。[夜の最終計測](timing-sun-at-night/summary.json)・[最終ZIP・実機記録・コンパイル結果の照合](sun-verification.json)
