# 溶岩のない白樺林で、画面全体の描画に時間がかかる理由

**候補9は採用保留。** 白樺・消灯で deferred と composite を合わせた GPU 時間の短縮は 0.089 / 0.111 ms だった。基準は両組とも 2.0 ms 以上。GPU フレーム全体は 0.119 / 0.059 ms 延びた。プレビュー8を引き続き比較基準とする。

消灯した白樺林で、プレビュー3の composite と deferred は、そこで使わない溶岩照明をフラグメントプログラムから外すと速くなった。カメラ周囲の 64³ セルに溶岩は 0 個。明るい空の下の同じ視点で、影を作る光線を実行していないときにも差が出る。水中や溶岩の近くで必要になる計算を持つこと自体が、この GPU では乾いた景色の描画時間に影響していた。[前回の 1.8.0 とプレビュー3の測定](../2026-11-22-gpu-profile/README.md)

## 原因を分けた実ゲーム測定

表は RTX 3080 Ti、2560×1440、12 チャンクで測った GPU タイムスタンプの平均 ms。各行は同じ 2 パックを対照 A、変更 A、変更 B、対照 B の順で別々に起動した結果。差は変更側から対照側を引いた値。フレーム全体には該当の draw 以外も含む。

| 一つずつ変えた条件 | 対象 draw の対照 → 変更 A | 対照 → 変更 B | draw 差 A / B | stage 差 A / B | GPU フレーム差 A / B |
| --- | ---: | ---: | ---: | ---: | ---: |
| composite の照明を 1.8.0 のランプ専用にする。pragma を保持 | 1.987 → 0.828 | 1.987 → 0.827 | −1.159 / −1.160 | −1.251 / −1.274 | −0.834 / −0.974 |
| 同じランプ専用 composite から NVIDIA の inline 128 を外す | 0.827 → 0.628 | 0.827 → 0.628 | −0.199 / −0.199 | −0.210 / −0.207 | −0.281 / −0.267 |
| deferred の保留画素の照明計算を除く。pragma と 5 出力を保持 | 1.827 → 0.412 | 1.834 → 0.426 | −1.416 / −1.408 | −1.529 / −1.446 | −1.386 / −1.359 |
| 同じ軽量 deferred から 5 番目の出力と C14 の読み戻しを除く | 0.412 → 0.401 | 0.428 → 0.390 | −0.011 / −0.038 | −0.066 / +0.006 | −0.090 / −0.185 |

判定窓は READY、F2 保存、3 バッチ除外後の連続約 10 秒。16 起動、合計 5,703 フレーム。全組で対照の quad/final と dispatch/begin1 が許容幅 max(0.10 ms, 10%) 内に収まった。各組の計測値と draw 回数を保存した。[集計 JSON](summary.json) · [各起動の証跡](runs/) · [4 種の診断 ZIP の作り方](diagnostics.py)

Iris が実際にリンクした頂点・フラグメントの GLSL を、時刻計測とは別の私有クライアントで取得した。1.8.0 の両フラグメントには NVIDIA 指示がなく、プレビュー3の両方に `#pragma optionNV(inline 128)` があった。ランプ専用の指示あり／なしで違うのはその行と同じ関数の名前だけ。各比較で反対側のプログラムと頂点ソースは一致した。deferred の先頭 4 出力は RGBA32F が 2 枚、RGBA16F が 2 枚。追加分は原寸 R16F。5 出力の軽量版でも C14 の sampler と出力は実際に有効だった。追加 MRT で 1.4 ms の大半を説明することはできない。保留画素の計算を外すと C15 を含む関連 sampler もリンク時に消える。ここで分けられたのはコードとそれに必要な入力を合わせたコスト。pragma の差はランプ専用ソースで測った値で、フルソースとの交互作用やレジスタ数、occupancy、メモリ帯域は直接観測していない。[提出ソースの全差分](submitted.diff) · [取得コード](capture/Capture.java) · [ZIP の内容とハッシュ](packs.json)

溶岩 1 セルを実際の面から捕捉して公開した GPU 試験でも、速くなった診断版をそのまま使えないことを確認した。水中散乱の C0 赤はプレビュー3が 0.005236783、ランプ専用版は 0。保留中の不透明面は 2.662391 と 0。溶岩を消すと両組とも同じ 0。これは線形 HDR 値。Minecraft の画面階調やフレーム時間とは単位が異なる。[NVIDIA](witness-nvidia.log) · [llvmpipe](witness-mesa.log)

## 単一プログラムの候補と画素検証

プレビュー8の上に idle-preview を重ねた。composite は乾いた視点で空気の処理を終えて返り、水中では溶岩を含む照明を呼ぶ。deferred は頂点で 128×1801 の R32UI 画像の (0,72) を一度読む。影に取り込んだ全グリッドが空なら、保留画素の照明を含まない関数に入る。別のレイアウトでは従来の関数を使う。同じリンク済みプログラムに両経路があり、5 出力と描画順は従来通り。カメラのタイルだけで判断すると、画面外の溶岩が照らす面を取りこぼし得る。shadowcomp2 の上側キャッシュは従来通り書く。前回の白樺・消灯の 1.8.0 → プレビュー3の差 +0.392 ms は dispatch 全体の値で、ストア単体のコストは未分離。[候補のソース](../../release/idle-preview/shaders/) · [プレビュー8と9の実際のバインド](summary.json)

候補 ZIP は `python3 tools/build.py --idle-preview` で build/lava-idle に生成した。SHA-256 は `4184d8cdf12634f108e3379d5b600de5009349916dfea26f7ad59f9190748f0f`。公開済み 1.8.0 とプレビュー3〜8を各 CLI から別ディレクトリへ再生成すると 7 本とも配布 ZIP とバイト一致した。

プレビュー8に経路試験をかけると空グリッドでも heavy entry=1 で失敗し、候補は deferred/composite とも 0。経路を識別するために書き換えたプログラムは、その確認だけに使った。実際に提出された未計装の GLSL に同じ入力を与えた 25 条件では、不透明面の C0/C4/C8/C10/C14、続く composite の C0、同じブルーム入力からの最終 RGBA8 と露出履歴 RG32F の全ビットが一致した。33×17 と 2560×1440、昼の空、水中、溶岩 1／9 セルと柱・松明の有無、濡れた葉、手持ち松明、溶岩の除去・復帰、144 セル、次元の霧を含む。予備試験で C14 テクスチャの寸法が読み出す画面より小さいことに気づき、全画素分を割り当てて再実行した。ここでの合否には修正後の full ログを使った。これらは入力を固定できる GPU 試験。実ゲームの F2 はステージと構図の照合に使う。[旧版での失敗](route-red-nvidia.log) · [RTX 3080 Ti](candidate-full-nvidia.log) · [Mesa llvmpipe](candidate-full-mesa.log) · [照合処理](../../tools/lava-idle-probe.h)


通常版の `make check` と既存の check-lava、check-ceiling、check-eye、check-ground、check-animal、check-canopy は全 7 件通過。候補 ZIP を展開したものにも通常プレイ回帰と同じ 6 種の機能プローブを適用し、7 件通過した。通常プレイ回帰の溶岩試験は 39 件通過、失敗 0。glcheck の中で報告される GPU 時間は試験用の場面の値で、上表の Minecraft の draw 時間と FPS の計算には使っていない。[通常版](historical-check.log) · [候補の通常プレイ回帰](regression-check.log) · [候補の溶岩検査](regression-check-lava.log)

各 GPU ジョブの起動前と描画ロック内で nvidia-smi と ps を確認し、ジョブを 1 件ずつ実行した。最初のソース取得では、開始合図の紙が消費された後もオフハンドに紙があると誤認したため、場面検証で停止した。両手が空という条件に直して新しい名前で再実行した。失敗分は計測に含めていない。[最初の記録](runs/gp-idle-src-stable/complete.json) · [再実行](runs/gp-idle-src-stable-retry1/complete.json)

## プレビュー8と候補9の実ゲーム測定
