# 葉影の光路コスト — アドバイザー所見(2026-11-21)

対象は `build/leaf-smooth-r2/shaders`(= release/shaders)。GPU計測は行っていない。FPS値はすべて既存ログからの引用。

## 0. 読み取った事実

- 実測値:`ground-evening`(松明1本、`torch_cell [207,64,359]`)は before 39.1 → accepted 32.8 → disk-r2 **13.8 FPS / P99 76.3 ms**。low-sun も 13.6 FPS。noon は 50.2 → 49.3 FPS とほぼ変わらない。つまり増えたのは、松明1本ぶんのローカル光の可視判定だけ(`timing-*/client.log`)。
- `lampVisibility`(`lib/local_lighting.glsl:166`):3本の試行光線のどれかに `apertures&2` が立つ(sprite付きの葉セルを1つでも横切る)と `count=35` になり、試行光線の結果は**捨てられる**。そのため1画素・1光源あたり35回の DDA を行う。受光面が葉の裏(`leafVolume`)なら、1回あたり最大48ステップ。
- 分岐が立つ条件は、光線が「どの距離で」「何枚の」葉を横切るかに関係なく同じ。森では受光点から松明までのほぼ全経路が葉を通るので、受光点の大半が35本の経路に入る。
- `lampVisibility` を使っているのは以下。いずれも35本に昇格しうる:
  - `gbuffers_terrain`(forward。`discard` があるので樹冠の重なりも全部シェーディングされる)
  - `shadowcomp2.csh`(バウンス。768×256 invocation × 4 subcell × 光源数)
  - `weather_light.glsl:111`
  - `illumination.glsl:21`(水面への入射。composite / water)
- `foliageSegment` はサンプルごとに sprite を `texelFetch` し、`pow(…,2.2)` で hue/sheet を計算し直している。これは slot ごとの定数で、32回繰り返す意味はない。

## 1. すぐ入れられ、見た目が変わらないもの(優先度順)

1. **昇格を許すのは見た目に効く受光面だけにする。** `lampVisibility` に `bool allowDisk` を追加する。`shadowcomp2`(拡散バウンス)、`weather_light`、`illumination`(水面入射の上向き放射照度)は常に false にし、従来の3点に固定する。いずれも低周波の積分量なので、葉のテクスチャの半影は見えない。壁は試行光線が引き続き判定するので、透けることはない。
2. **`foliageSegment` のループ不変量を外へ出す。** slot ごとの `sheet`(sprite の fetch と pow を含む)を1回だけ計算して引数で渡す。結果はビット単位で同じ。
3. **試行光線を捨てない点集合にする(任意)。** 3回回転対称の33点(3点×11リング、試行光線をそのうち1リングに含める)を等重みで使えば、追加は30本で済み、三重輪郭の原因になった「試行光線だけ重みが重い」状態にもならない。削減幅は小さいので、2の後で十分。

## 2. 本命:有限光源の足跡で葉マスクを前置フィルタする(32点積分の置き換え)

一枚の切り抜き面だけを横切る場合、円盤光源に対する32点積分は「被覆マスクを、遮蔽面上の足跡で畳み込んだもの」の近似に等しい。足跡は、受光点から光源円盤へ張った円錐が葉の面を切る断面である。そのため **中心光線1本 + 面ごとの箱フィルタ1回** で置き換えられる。

- 足跡の大きさ:受光点からの距離 s で面を横切り、光路長を d、光源半径を R(松明 0.13 / 立方体 0.42)とすると、足跡の半径は ρ = R·s/d。面法線を n、光の向きを l とし、面内軸 u については `w = u − n·(l·u)/(l·n)`、半幅は `e_u = ρ·sqrt(|w|² − (w·l)²)`(v も同様)。
- 箱の幅は**分散が一致するように**決める(単位は m、texel = 1/16 m):`W_u = sqrt((1/16)² + 3·e_u²)`。
  これは「最近傍マスク ⊗ 箱(W)」が「最近傍マスク ⊗ 箱(1 texel)(=現行の bilinear `leafSurfaceCoverage`)⊗ 円盤(ρ)」と同じ分散になる幅である。ρ→0 で現行の bilinear と完全に一致するので、**しきい値を切り替えずに使え、動いても不連続が出ない**。ρ が大きい側では 1.73ρ で、等面積の 1.77ρ とほぼ等しい。
- 実装:`leaf_mask_capture.glsl` は slot ごとに書き手が1つなので、そこで 17×17 の summed-area table(各値 ≤256、2値/uint にパック)も作る。シェーダー側の被覆は SAT を4回 fetch した値 / 箱の面積。sheet/tint は slot 定数なので `mix(1,sheet,E[a])` は厳密。入射面と出射面の積は E[a]·E[b] で近似する(ρ が小さいときは厳密で、大きいほど面間の相関は弱まる)。`medium` と `pow(faces,min(1,8·dist))` は中心光線の弦長で評価する。
- **フォールバック**(既存の32点経路へ。すべて保守的な判定):
  - (a) 箱が当該の面の [0,1]² をはみ出す。はみ出した先では、ディスク内の光線が隣の面から入るか、葉を外れる。
  - (b) 中心光線の弦長が 0.125 m 未満(角をかすめる場合)。
  - (c) 下の太い光線検査で不合格。
  - (d) `entityTest` が真。
  - (e) slot==0 または sprite 未登録。

### 太い光線(fat ray)検査:壁を透かさない保証
中心光線の DDA の各セル区間 [t,end] で、円錐の半径 r(end)=R·end/d を使う。中心点 ± r の AABB が隣のセルにはみ出したら、はみ出した先のセル(通常は0個、最大7個)を fetch する。shape が 0(空気・enclosed air)以外ならフォールバックする。対象の1枚の葉セル自身は除く。光源の所属セル(goal)は除外してよい。壁付け松明は壁から 0.29 m、R=0.13 なので、円盤は自分のセル内に収まる。

これで、円錐の内側に試行光線が拾えない壁・扉・ガラス・別の葉が無いことを、追加の光線なしで保証できる。

## 3. 親の案(試行3本が同じ1枚の葉だけを横切る → その1セルを32点積分)の欠陥

1. **試行3本は円盤の 0.66R にしかない。** 外周のリングと3本の間を通る板・扉の画素・柵・別の葉の角を見逃す。「3本が同じ葉しか通らない」だけでは、円錐の中が空であることにならない。上の太い光線検査を条件に加えること。加えない場合、現行の32点(全経路を追跡)より壁際で明るくなりうる。
2. 3本のセル列が互いに違う場合、それぞれの光線は1枚しか通らなくても、間に別のジオメトリがありうる。少なくとも「3本の DDA セル列が同じ」を条件にすること。
3. 1セル32点でも、`foliageSegment` の不変量(§1-2)と、`outerExit` 用の隣接セル fetch が32回繰り返される。出射側の隣接セル判定はセル単位なので1回で済む。
4. 樹冠では「1枚だけ」の条件がほぼ成立しないため、**森林フレームの主要コストは残る**。単独の葉は速くなるが、33→13.8 の大半は多重交差と葉裏の受光面から来ている可能性が高い。これは未計測なので、下の §5 で確認してほしい。

## 4. 濃い樹冠・遠方の上限(単独葉の要件の外側)

- **交差ごとの前置フィルタの積:** 中心光線が横切る sprite 付きの各面に、§2 の箱フィルタをそれぞれ適用して掛け合わせる。足跡は受光点の近くで小さく(現行の bilinear にほぼ一致)、光源の近くで大きく(平均透過に近づく)なるので、物理的な順序は保たれる。相関を無視する誤差が大きいのは、足跡が数 texel 程度の面が2枚以上重なる場合に限られる。太い光線検査で隣の葉にはみ出したら、従来の経路へ戻す。
- **画面上の半影幅の上限:** 受光面上の半影幅 `w = 2R·s/(d−s)` を、受光点での画素の大きさ(`z·2tan(fov/2)/1440`)で割る。1 px 未満なら円盤を省き、中心光線だけにする。三重輪郭の間隔も w 以下なので見えない。
- **葉裏の受光面(`leafVolume`):** 透過光は受光した葉自身のアトラス柄と透過率で変調されるので、昇格させないか、§2 の推定器だけを使う。48ステップ × 35本はここで最も重い。
- **画素ごとの作業予算で打ち切ってはいけない。** 光源リストは 8 m タイルごとなので、予算の差がタイル境界で継ぎ目になり、光源の並びが変わると明滅する。判定は上のような幾何だけにする。幾何による判定は毎フレーム決定的で、履歴バッファを使わないので、動いてもゴーストは出ない。

## 5. 全画素が重い分岐に巻き込まれる問題

- 葉は forward(`gbuffers_terrain`、`discard` あり)で照明されている。そのため、(i) warp 内に1レーンでも35本のレーンがあれば全レーンが待つ。(ii) 樹冠の重なりで、後から上書きされる断片まで35本を払う。
- 構造的な解決策は二段化である。forward では試行3本の結果と「昇格が必要」フラグを書く。続いて deferred の compute で、可視画素のうちフラグが立った画素だけを atomic counter で詰めたリストにして、差分 `albedo·energy·nl·(vis32 − vis3)` を加算する。これで重なりと発散が同時に消える。代わりに、受光点・法線・葉セル・光源インデックスを G-buffer に残す必要があり、作業は大きい。§2 と §4 で昇格する画素がまれになれば、不要になるかもしれない。
- 計測は不要という指示なので、ここでは提案にとどめる:経路ごとの色分けデバッグ表示(試行のみ / SAT / 32点フォールバック)と、forward 断片のうち昇格した数の atomic カウント。これらがあれば、§3-4 の「森林コストの主因」が真か判断できる。

## 6. 検証(GPU不要)

`penumbra/oracle.py` には、`trace`、`shader_coverage`、`mix32` と `dense1024` の点集合がある。ここに §2 の推定器を「中心光線 + `W_u` の箱積分」として追加する。壁 ROI で `rmse(SAT, dense1024) ≤ rmse(mix32, dense1024)` を満たし、かつ `find_edges` で多重輪郭が検出されないことを、「現行32点相当」の受け入れ条件にする。等分散の箱で足りなければ、円盤を縦横2つの長方形の和から重なりを引いた形で近似する(SAT 12回 / 面)。

## 推奨順

§1-1 → §1-2 → §2(太い光線検査つき。単独の葉はこれで32点を置き換える)→ §4(樹冠・遠方・葉裏)→ 必要なら §5 の二段化。親の1セル32点案を採るなら、§3-1 と §3-2 の条件を必ず加えること。
