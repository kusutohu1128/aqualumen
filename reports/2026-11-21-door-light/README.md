# 扉を通る二色のランタンと、木陰に置く松明

Aqualumen 1.6.0では、ランタンから受光面までの間にある扉の向き、厚さ、小窓を調べる。奥の部屋から手前の白い床へ届く暖色はダークオークの扉を閉めると消え、床の横に置いた魂のランタンはそのまま青く光る。オークの小窓とアカシアの格子は白壁に違う模様を落とす。[実ゲームの家](house-settled.jpg) · [扉の投影](window/shipped-projection.jpg)

## 木陰に松明を置く

配布ZIPを選んだMinecraftで、同じ午後のシラカバを同じ位置から撮った。幹の85×70画素の平均RGB8は、消灯で (129.4, 131.2, 130.4)、松明で (171.9, 147.4, 127.6)、魂の松明で (125.3, 146.8, 155.4)。離れた草の赤成分の変化は通常の松明で約4階調だった。幹に届く局所光が変わっても、樹冠が地面に落とす日陰は残る。RTX 3080 TiのネイティブOpenGL、1440p・12チャンクで通常の松明を置いた区間は平均39.6 FPS、P99 27.44 ms。役割名は既存の検証基盤を使っているが、この3場面は同じ午後の時刻・カメラで撮影している。[点灯前・松明・魂の松明の実画像](birch.jpg) · [画素値と時間](birch.json) · [元のゲーム記録](birch-native/capture/run.json)

## 同じ家で一灯ずつ調べる

Minecraft Java 1.21.1、Iris 1.8.8、Sodium 0.6.9、接触波紋Mod 0.2.0、RTX 3080 Ti。独立した検証ワールドの複製に、撮影中は位置が動かない白い床、滑らかな石、西向きの窓、間仕切りのある家を建てた。ゲーム内時刻を11800に固定した。元の1.5.0と新しい配布ZIPで、開閉、各灯の点灯・消灯、扉の撤去、牛が戸口に立った状態など18通りずつ撮影した。両方の灯りを同時に点ける写真に加えて、それぞれを取り除いた写真を保存した。[1.5.0の撮影記録](before-r1/complete.json) · [1.6.0の撮影記録](shipped/complete.json)

白い床の中央では、吊りランタンの点灯による明るさの差が、1.5.0は扉を開けても −0.00010 だった。1.6.0では開けると +0.0554、閉めると −0.0017、扉を外すと +0.0584。手前の石で魂のランタンを点けた効果は、開けたとき +0.0726、閉めたとき +0.0738 だった。各値は11×11画素の平均RGBをsRGBから線形化した表示輝度の差で、露出とトーン処理を含む。わずかな負値も測定どおりに残した。[受光点と点灯・消灯の全測定値](house-results.json) · [受光点の位置](patches.jpg)

同じ配布ZIPで八つの条件を再撮影した。初回ワールド描画から100秒以上待ち、両方のランタンを消した状態、暖色のみ、戸口の牛、開閉後に元へ戻した画面を保存した。開扉時と、同じ開扉状態に戻したときの白床は、対応するRGB各成分で最大0.405階調の差だった。手前の魂のランタンを撤去した石と本棚側には、奥の灯りの切り替えで別の暗部が現れたため、この場所を牛の影として扱っていない。主視点のまま待った1.5.0でも同じ暗部を再現した。[再撮影の全画素測定](house-settled-results.json) · [再撮影の場面と受光点](shipped-settled/plan.json)

### 本棚の前の石が暗くなった理由を調べる

建築したセッションの中で、魂のランタンを撤去し、奥の暖色だけを点けると、本棚手前の滑らかな石が約13階調暗くなる場合があった。画面に届く前の値とゲームの地形入力を別々に読み戻した。同じ石で、太陽の直射はゼロ、材質の輝度は0.334、頂点AOは0.998、露出は1.004。奥のランタンを点けると、地形の頂点から補間された天空光だけが0.957から0.555に下がり、天空拡散光は0.0778から0.0434に下がった。石に届いた局所光の輝度は両方とも0.00011未満だった。点灯に応じて生じる差のうち、暗転に見合う大きさがあったのはこの天空光だった。[最終表示直前の測定](display-stage-results.json) · [地形の入力・天空光・太陽・松明の同時測定](receiver-stage-results.json)

家を保存してゲームを終了し、その複製を再び読み込んだ。屋根も扉もカメラも動かさず、奥のランタンだけを二度点灯・消灯した。石の周囲36セルで、クライアントの天空光は4回とも保存ファイルの値と一致した。画面上の同じ石に補間された天空光も4回とも0.52995で、点灯と消灯の間で表示の各成分に生じた差は最大0.28階調だった。建築直後に同じセッションで撮った石の暗転は、この再読込条件では再現しなかった。どの段階のチャンク更新で古い値が残ったかは特定できていない。[保存データの照合](sky-control/saved-cells.json) · [実クライアントの36セルと画像](sky-control/settled/complete.json) · [同じ石の4回の測定](sky-control/settled-results.json)

同じ保存状態の家で診断用シェーダーを外し、配布ZIPと通常のMod三つだけでも撮影した。魂のランタンを点けたまま奥のランタンを追加すると、白床の表示輝度は開扉時に0.06965増え、閉扉時の差は0.00000だった。同じとき本棚前の石の差は開扉時0.00040、閉扉時0.00000。魂のランタン自体を点けた効果は、その石で開扉時+0.08566、閉扉時+0.08430だった。各値はRGB8を画素ごとに線形化した表示輝度。撮影は最初の7場面までサーバーがカメラとブロック状態を確認し、その後はカメラの高さがずれたため採用を止めた。同じセーブの別の複製で視点を戻して残り2場面と開扉の対照を撮った。再起動の前後で開扉対照の白床は同じ値だった。[通常版の4枚比較](sky-control/ordinary-house.jpg) · [受光点と全測定](sky-control/ordinary-results.json) · [初回の撮影7場面](sky-control/ordinary/partial.json) · [残りと対照の撮影](sky-control/ordinary-finish/complete.json)

配布ZIPを入れた通常のサバイバルクライアントで、壁のレバーを右クリックし、閉→開→閉→開→閉と切り替えた。サーバーがレバーの通電と扉の上下の開閉を確認し、カメラを固定したまま床に差す光が二度戻った。[実際の右クリックで開閉する28.8秒の動画](interaction/shipped/lever-door.mp4) · [入力・ブロック状態・フレーム測定](interaction/shipped/complete.json) · [Claude Opusによる状態別の照合](house-advisor.md)

## 隙間と半影

別の小部屋では扉をカメラの外に置き、ランタンの前の扉だけを取り替えた。白壁にオークは四つの窓、アカシアは細長い格子が映り、ダークオークは暖色を遮った。シェーダーはMinecraftがその場で描くテクスチャから上下各16×16の透明・不透明を取得し、厚さ3/16ブロックの板の中を光線が横切る区間を追う。設置した光、手に持つ光、一回反射の経路で同じ格子を参照する。標準・高画質設定では、動物の遮蔽候補に重ならず扉のあるセルを通った光路を、発光面上の32点で調べる。動物と重なる光路は3点、軽量設定は中心の1点を用いる。[実装](../../release/shaders/lib/door_transmission.glsl) · [面光源積分の参考文献](https://pbr-book.org/4ed/Light_Sources/Area_Lights)

640通りのバニラ扉モデルをオフラインで読んで向きと面を確かめた。別の実ゲームの診断画像では、オーク・開いたオーク・ダークオーク・アカシアの上下について、実際にGPUに配られた透明度マスクの全2,048ビットがゲームの資源と一致した。扉の撤去後には上下とも空になった。高解像度リソースパックの細部はこの16×16格子に標本化される。[モデルの内訳](models.json) · [実ゲームで読み戻したビット](window/states.json)

3点サンプルの候補では、小窓が白壁に落とす半影に段差が見えた。オークの窓の縁188画素で、実ゲームの赤成分を同じ行の明部・暗部で正規化し、独立した4,096点の面光源積分と比べた。3点で0.171だった二乗平均平方根誤差は、32点の候補で0.030になった。積分を16,384点に増やしたときの基準値の最大変化は0.0016だった。[半影の実画像](window/shipped-edge-comparison.jpg) · [計算条件と誤差](window/shipped-edge-profile.json)

Claude Sonnetの独立したGPU検査で、光線と扉の板・テクスチャの境界が完全に重なる6件に左右差が見つかった。隣の領域も調べて接線と木の内部を区別した。修正後は、隣り合う扉の継ぎ目32件を含む63,199件がRTX 3080 Ti上で通った。これには設置光・手持ち光、カメラから約10万mの座標への移動、上下、開閉、表裏の区別を含む。[修正前の失敗](gpu-door-after-r1.log) · [修正後の結果](gpu-coplanar-joins.log) · [水・太陽・間接光を含む通常版の回帰検査](gpu-release.log)

配布ZIPには通常版のシェーダー・設定100ファイルとライセンスが入る。再ビルドしたZIPはバイト単位で一致した。[配布物の照合](package.json)

## 自分の操作で試す

Aqualumen Labのシングルプレイに **Aqualumen Lantern House** を追加した。クリエイティブで、夕暮れを固定している。空きスロットは9番、松明は1番。屋外では幹の松明の設置と回収、室内では二つの灯りの点灯と扉の開閉を試せる。配布したワールドの複製を通常のMinecraftで開き、道から玄関まで歩き、右クリックで玄関の扉を開けて室内に入った。終了後のセーブでも扉の上下が開いていた。[配布ワールド](../../dist/Aqualumen-Lantern-House.zip) · [出発地点](playable/smoke/01-spawn.png) · [入室後](playable/smoke/04-inside-room-a.png) · [入力と保存位置](playable/smoke/smoke.json)

元のAqualumen Labでも通常版1.6.0と接触波紋Mod 0.2.0の読み込みを確認した。検証用Modは外し、計測は無効。既存の通常セーブ41ファイルを照合し、新しく追加した見本ワールドの5ファイルが配布ZIPと一致することを確認した。[通常構成の実機起動](normal-smoke.json) · [見本ワールドの導入記録](playable-install.json) · [タイトル画面への復帰](handoff.json)
