# 松明の光が幹と段差の角をかすめるとき

幹や地面が松明を半分隠しているとき、受光点を少しずらしただけで、火が全部見えるという計算結果に飛ぶ場合があった。どの程度実際の画面に現れるかを知るため、GPUでの幾何計算と、白樺林のMinecraft画面を調べた。出発点は[設置松明の二つの影を扱う版](../2026-11-23-mixed-occluders/README.md)。

[配布用の地形版と実機結果](#配布用の地形版)・[通常画面での見え方](#通常画面にどれだけ映るか)・[サバイバルの二灯](#サバイバルの続き)

## 角での計算

これまで使った67,599入力には、実際に白壁を描いたときの受光位置が含まれる。新たに、二つの直方体の面や辺と、受光点や円盤状の火の中心がほぼ一直線になる60,000入力を加えた。後者は誤差を探すために偏らせた合成入力で、出現頻度を通常プレイに当てはめることはできない。GPUの出力を、倍精度で影の多角形を切り詰めて面積を計算する独立実装と照合した。[入力生成と実行](integral.py)・[倍精度参照](../2026-11-23-mixed-occluders/footprint.cpp)

追加した60,000入力のうち、前の版で火の可視率の誤差が2/255を超えたのはRTX 3080 Tiで3,381件、Mesa llvmpipeで3,352件。RTXでは可視率33.43%を100%と判定した例がある。Mesaではほぼ半分見える火を完全に隠した例があった。今までの白壁で位置を細かく動かした37,376入力では、前の版もこの閾値に収まった。[従来版の結果](polygon.json)・[白壁の細分](grove-wall.json)

一つの直方体が火を隠す面積を求めるとき、角度を測る基準を、円盤の中心から影の外にある円周上の点に移した。面積は円盤を横切る直線部分から求まる。二つの直方体がそれぞれ一本の縁だけで火を切る場合は、その二本の線分を使って共通部分を計算できる。複数の縁が関わる場合には残りの制約も適用する。この版は127,599入力すべてで、両ドライバとも倍精度参照との差が0.5/255以内だった。[直方体ごとの処理](edges.py)・[二本の縁](caps.glsl)・[GPUと参照の比較](caps.json)

## 実ゲームの比較条件

Minecraft Java 1.21.1、Iris 1.8.8、Sodium 0.6.9、Physics 0.2.0。RTXの隔離コピーだけでLighting Compiler 0.3.0を有効にした。通常描画は2560×1440・12チャンク、診断画像は1280×720。松明4本の位置、時刻9800、カメラ角度と手持ち品を固定した。可視率は露出・色調整の前の値で、通常画面の輝度には日光と間接光も含まれる。

Claude Fable 5.2は、同じ森でカメラを動かし、旧版・試作・独立参照を比べることを提案した。実験ではブロック境界の前後8 cmを2 cmずつ動かして5地点に停止し、各地点の静止後にF2画像を取得する。横8画素ごと、縦は毎行の測定で、同じ地表が占める画素の火の可視率を比較する。各地点で同じブロック面を識別し、別の地点に視線が移った分は独立した8,192本の光線で見積もる。葉など光の透過率を独立に確定できない経路は集計から除く。[Fableの助言](advisor-answer.txt)・[ゲーム内の操作](sweep.py)・[画素の対応づけと判定](sweep_score.py)

## Minecraftのブロック寸法と実画面

白樺林の撮影ではロード直後の最初の地点でチャンクが揃わず、検証が撮影を見送った回がある。採用した画像は各姿勢で、視点・松明・支持ブロック・時刻・周囲のチャンクの読み込みをゲーム側が確認した後のもの。[初回の判定と再訪時の記録](birch-motion24/client.log)

松明をブロックの中心（高さ0.64 m）に置き、実寸の幹と土、整数座標の受光面、法線方向2.5 cmの光線の開始位置を使う104,247条件も生成した。角に狙いをつけた条件のうち半影は31,368件。前の版の誤差が2/255を超えたのはRTXで7,019件、Mesaで7,414件。二本の縁を扱う試作では両方とも0件だった。RTXの最大誤差は、前の版が可視率0.26%、倍精度参照が50%。独立に円盤内の131,072点へ光線を飛ばした結果も50%だった。[実寸の条件と結果](voxel-cases.json)・[別の光線計算](ray-check.json)

その配置を隔離したMinecraftワールドにも建てた。松明と土、白樺2段、白壁を設置し、カメラの中心列を問題の座標に合わせ、左右2 mmにも動かした。3地点の計41,692件の壁の半影で、表示前の可視率の新旧差は最大1/255。狙った中央画素は従来版も新しい版も128/255で、独立参照は50%だった。入力を直接GPUへ与えた際の0.26%は、この実画面では再現できていない。[ワールドの配置](grazing_room.py)・[画素と世界座標](corner.json)

自然の白樺林5地点の32,540件の半影でも、新旧の可視率が変わったのは1件・1/255だけだった。地点間で同じブロック面を追えた24,871組では、参照を差し引いた変化が旧版より2/255を超えて悪化した組も改善した組も0。通常描画の別の固定視点では、草地・樹皮などの半影33,675地点中33,500地点で表示RGBが完全一致した。別起動の同じシェーダー同士にも差があるため、通常描画の最大差だけから原因は確定できない。[移動時の可視率](birch-sweep.json)・[通常画面と同じシェーダーの対照](display.json)

## 少ない光線で遮蔽物を見つけるには

Fableが挙げた「光線が当たったブロックの形から影を求める」案を、白樺林の中央視点の保存済み画像とワールドから調べた。形状を事前分類できなかった不透明な地表の半影を光源ごとに128件ずつ、計512件抽出した。既存の3本が最初に当たるブロックだけを使っても、火の面積をどれだけ正確に計算できるかを8,192本の光線で求めた。106件では3本とも遮蔽物を外した。66件で可視率を10ポイント以上過大に見積もり、最大の例では75.0%見える火を完全に見えると判定した。[助言](advisor-motion-answer.txt)・[抽出と交差判定](pilot_blocks.py)

同じ512件で、地面から見た火の円盤全体を囲う範囲に触れるブロックを拾うと、候補が1個の場所が336件、2個が125件、3〜5個が51件だった。それらの候補で8,192本の光線を追った可視率は、512件すべてで全地形を使った参照と一致した。既存のシェーダーにはこの範囲の判定があり、1〜2個の候補なら現在の幾何計算に渡せる。今回の数値はCPUでの候補選択の検証で、GPUで候補を列挙する負荷と、葉や動物が重なる経路は別途測定が必要になる。[件数と反例の座標](pilot-blocks-extent.json)・[既存のGLSLでの範囲判定](../../release/shaders/lib/leaf_disk.glsl)

この範囲判定を設置灯の実装に組み込み、火を隠しうる塊が2個までの場所で影の面積を直接求めた。白樺林で最初に見つけた草地の可視率は39.6%から36.1%となり、参照の39.4%から36.0%に近づいた。5地点の半影32,548件では平均誤差2.29から0.26ポイント、同一ブロック内の10ポイント超の誤変化は617から34件になった。一方、ブロック境界をまたいだ271組では0から9件に増えた。通常描画は95フレームで平均106.06 ms、P99 115.92 ms。[実装](cone.glsl)・[同じ草地での各方式](grass-light-alternatives.png)・[5地点全体](cone-sweep.json)・[描画時間](../2026-11-23-torch-density/gp-density-cone/summary.json)

この版で最も大きくずれた4地点をワールド座標に戻すと、いずれも (205,64,364)、(206,64,363)、(207,64,362) の3ブロックが斜めに並んで火にかかっていた。2個までを扱う上記の版は、ここでは3本の光線に戻る。最も大きい例では、実測66.7%から0%に対して参照は32.9%から28.7%だった。[位置と光路](cone-sweep.json)・[該当する3ブロック](diagonal-cubes.json)

## 配布用の地形版

地形版では、火の円盤に届きうる不透明な立方体が1〜2個なら影の面積を求め、3〜8個なら一度列挙した箱を使って円盤上の64点で交差を調べる。各点でボクセルの材質を繰り返し読み出す必要がなく、どの箱が他の箱を隠しても重なりを二重に数えない。動物が近づくと、地形の間を実際に通る光線について現在の動物の形状を調べる。透過材質や候補が8個を超える経路では従来の光線追跡を使う。[シェーダー](../../release/torch-shadow-geometry/shaders/lib/local_lighting.glsl)・[配布ZIP](../../dist/Aqualumen-Torch-Shadow-Geometry.zip)

初期試作で斜めの3ブロックの場所は31.4%から28.2%になった。白樺の草地では39.6%から36.1%。5姿勢の半影32,474件では、火の可視率の平均絶対誤差が輪郭補正版の2.29ポイントから0.12ポイントになった。同一ブロック内24,789組で10ポイント超の誤変化は617件から0件、最大誤差は63.31から5.49ポイント。境界をまたいだ269組でも0件で、変化の最大誤差は1.87ポイントだった。草地の図の右端1点はこの試作の診断画像でその松明を読み取れず、欠測として空けた。2560×1440・4灯ではGPU計測を外した97フレームの平均が104.03 ms、P99が109.87 msだった。[5姿勢のグラフ](geometry-light.png)・[個々の測定値](geometry-light.json)・[地表全体の誤差](cone64-sweep.json)・[初期試作の通常フレーム時間](../2026-11-23-torch-density/gp-density-cone64/summary.json)

幹の撤去と復元を含む試験の初回は、牛の通過後に観測プロセスが終了コード143で停止した。この隔離Minecraftを終了し、その時点の6場面を保存した。初回は集計から除いた。[中断時のファイルと終了記録](cone64-animal/interruption.json)

10場面を完走した地形版の初期試作では、幹を切ると壁の11,422地点で火全体が見え、植え直すと11,422地点すべてで元の可視率に戻った。牛が暗くした5,325地点も通過後にはすべて元に戻った。一方、牛の体が光路に掛からない反対の壁では、通過中に452地点のうち148地点の可視率が変わり、最大差は48/255だった。松明に対する牛の大まかな当たり判定に入った段階で、静止した幹の面積計算まで3点の補間に切り替わる経路があった。[初期試作の10場面](cone64-animal-edits/complete.json)・[通過中と通過後の測定](cone64-animal.json)

配布用の修正では、牛が近づいてもまず同じ方法で地形が隠す面積を計算する。3個以上の箱に囲まれた場合も、地形を抜ける円盤上の標本についてだけ牛の三角形を調べる。再度牛を4.62 m歩かせると、光路から外れた反対側の壁452地点は通過中もすべて一致した。牛が実際に暗くした5,325地点は通過後に全地点で復帰した。幹の撤去と再設置では11,422地点、土の撤去では6,253地点で元へ戻り、消灯後にこの松明を評価した地点は0。[配布版と同じ光学処理での10場面](joint-animal/complete.json)・[撤去・復元・通過後の数値](joint-animal.json)

牛の修正を含めて昼の白樺林を再撮影した。輪郭補正版、24点版、地形版の三者で同じ地表・光源を照合できた半影32,505件の平均誤差は2.29、0.53、0.12ポイント。同一ブロック内の24,856組で10ポイント超の誤変化は617、3、0件だった。隣のブロックへ移る270組では三者とも0件。草地と斜めの3ブロックの両地点で今回の5姿勢すべてを照合できた。[最終版のグラフ](joint-light.png)・[測定値](joint-light.json)・[三者共通の比較](final-comparison.json)

配布用ZIPで同じ4灯を計測した。2560×1440・12チャンクでGPUタイムスタンプを外した連続95フレームは平均105.97 ms、P99 117.51 msだった。輪郭補正版の平均69.01 msに対し36.96 ms増、24点版の215.68 msに対し109.72 ms減。各版とも同じ固定視点での約10秒であり、最低FPSや別のワールドでの負荷はこの値から決まらない。[配布用地形版のフレーム間隔](../2026-11-23-torch-density/gp-density-geometry/summary.json)

配布用ZIPで夜に54.17秒・1,326フレーム描画してから、同じく暗さに慣れた輪郭補正版と比較した。昼の診断でいずれかの松明の可視率が10ポイント以上変わった地表は、共通する左姿勢で860地点、中央で900地点。夜の通常画像での表示輝度差は中央値1.00・0.93階調、95パーセンタイル3.58・3.78階調だった。全光源の可視率が一致した地表では両姿勢とも中央値0、95パーセンタイル0.21階調。この暗い草地では、火の可視率の段差を減らしても、夜の2枚で最終画素に現れる差は小さい。[夜の実画面](settled-night-grass-geometry.png)・[暗順応・測定地点と表示値](settled-night-ordinary-geometry.json)

別実行でプロファイラを有効にした配布版の平均GPUフレームは99.43 ms。地形の全画面照明が57.46 ms、葉・草などの切り抜き描画が10.67 msだった。24点版では同じ地形照明が166.13 ms、輪郭補正版では22.95 msだった。画質を保って軽くするうえで最も大きい計測対象はこの地形照明に残る。[配布版のGPU時間](../2026-11-23-torch-density/gp-density-geometry-gpu/summary.json)
