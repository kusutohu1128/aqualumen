# 幹が松明全体を隠すときの描画負荷

雨のオーク林の比較を踏まえ、松明の影を軽くする試作をプレビュー11から作った。最初の光線が完全に不透明な1 mの立方体に当たったときだけ、その光線がブロック内を通過する中点を記録する。光源中心までの区間で同じ割合の位置を取り、有限な光源面の全光線がその断面でブロック内部を通るかを調べる。立方体の中心からの各軸の距離に、光源半径×区間の割合を加えても半辺（丸め余裕0.0005 m込みで0.4995 m）に達しなければ、ブロックは光源面全体を隠す。設置灯自身のセルは事前に除外する。この条件を満たす場合に残りのサンプルを省く。[試作の生成と判定式](candidate.py)

この試作はGPUに過去フレームの可視率を保存しない。幹の縁や隙間で全遮蔽を証明できない点は、元と同じ光線・葉・ドア・動物の遮蔽処理を通る。光源の距離や更新頻度は通常のプレビュー11と同じ。[Fableの方向性レビュー](../2026-11-23-wet-oak-motion/advisor.txt)・[入力と実GPU照合の手順](verify.py)

設置灯を使う7配置・計6,600地点で、プレビュー11と試作の光源可視率を比較した。RTX 3080 TiとMesa llvmpipeの両方で、1,347地点で計算を省略し、元の版との値の差は0件だった。半影の788地点も比較に含む。省略した全地点について、独立したCPUの交差計算で光源の中心・面内768点・円周256点を検査した。計1,380,675本のうち不透明なブロックを通らずに届く光線は0本だった。これは設置灯の遮蔽の試験で、手持ち光源と移動中の生物はこの試験に含まない。[両レンダラーの結果](visibility.json)・[独立した交差計算](disk_check.py)・[光線数と結果](opaque-disk.json)

## 配布版で手持ちの松明と動く牛を比較

[プレビュー12のZIP](../../dist/Aqualumen-1.9.0-preview.12.zip) は `python3 tools/build.py --torch-umbra-preview` で再生成できる。白樺林で計測した試作と展開後の139ファイルが全て一致し、プレビュー11から変わるソースは `local_lighting.glsl` 一つ。実Minecraftに読み込ませた配布ZIPのSHA-256は `be935f1b5b30b581e5a3539c2031bd1d0d5fcf26647c28fd4bde42567c954ab2`。[アーカイブの照合](package.json)・[Mesaで全プログラムをコンパイル・リンク](link-mesa.log)・[エンティティ影のMesa回帰検査](entity-mesa.log)

Minecraft 1.21.1・RTX 3080 Ti・1280×720の同じ部屋をプレビュー11と12で比較した。高さ2ブロックのオークの柱を間に置き、手持ちの松明とプレイヤーを1.4 m横に動かした。柱の有無を切り替えた同一視点で、柱が光源全体を隠し、かつカメラから見える壁の点を抽出した。左からは710点で表示輝度が中央値22.26階調、右からは457点で24.26階調暗くなった。松明を直接見通す壁ではそれぞれ3.14、1.93階調の変化。プレビュー11と12で両方の中央値が一致した。[実画面6枚](moving-comparison.jpg)・[世界座標と遮蔽の計算](motion_results.py)・[12条件の全データ](moving.json)

暖色と青の二灯の間を牛が4.44 m歩いた。牛の体に重ならず、両方の灯りが届く背後の壁の小領域で、赤と青のチャンネル差を0.25秒ずつ記録した。プレビュー12では静止時の28.30から−0.56まで下がり、続いて54.95まで上がり、牛が去ると28.06に戻った。プレビュー11でも28.03→−1.13→54.59→28.27と同じ順序だった。手持ち灯と牛を含む、入場直後を除いた11条件のF2比較では対象領域の差は最大1階調。入場直後の二灯だけの条件では最大11階調の差があり、どちらの版も短い撮影中に壁全体が明るくなっていた。後半に同じ空室へ戻ったときは、その壁のF2画素は完全に一致した。[牛が歩く実映像](moving-umbra-r2/crossing.mp4)・[サーバーが記録した位置](moving-umbra-r2/trajectory.json)・[基準版](moving-reference/complete.json)・[配布版](moving-umbra-r2/complete.json)

手持ち光源の終点を含む6,600地点をRTXとMesaでも検査した。両方で1,834地点の追加計算を省き、元の版との可視率差は0件。省略地点から光源の円周を含む1,879,850本を独立に検査し、全ての光線が不透明な立方体を通った。最初の試作での実ゲーム撮影は、監視中にMesaのglcheckも起動してしまい中断された。中断した8条件を合格扱いせず、配布ZIPで同じ順序の12条件を単独で撮り直した。[GPUの結果](carried-visibility.json)・[独立照合](carried-disk.json)・[中断記録](moving-umbra/complete.json)

### 柱の影の縁に残る段差

柱を横から照らした実画面には、半影の縁に段が見える。この版は影の内側の計算を省き、境界にはプレビュー11と同じ3点サンプルを使う。実ゲームと同じ松明・柱・壁の配置で、カメラから見える壁を1 cm間隔でサンプルし、半影に入る点の可視率を光源面の8,192点による計算と比べた。3点サンプルの平均絶対誤差は左側72点で0.117、右側51点で0.090（可視率0〜1）。これは光源の見える割合の誤差で、表示画素の輝度誤差とは単位が異なる。角と縁の改善には、この手持ち灯の場面を前回の設置灯のオーク林と併用する。[影の縁のグラフ](wall-edge.png)・[照明の断面計算と対応する実画素](wall-edge.json)・[設置灯での過去の面積積分と負荷](../2026-11-23-oak-shadow/README.md)

同じ位置で、柱の輪郭のうち一本の直線だけが光源円盤を横切る場合に、円の弦で切り取られる面積を直接求めた。この部屋の左右123点はすべてこの条件を満たし、8,192点の基準との最大差は0.0011未満だった。ここでは柱全体と、光源の手前にほかの遮蔽物がないことが既知。一般の地形でその条件を効率よく判定する実装と、動く影の実機比較が残る。プレビュー12は従来の境界処理を使う。[断面と円弧面積の計算](wall_edge.py)

## 牧草地の下に二色の灯りを置く

## 雨の草に落ちる影についての助言

Fableは、足や腕のアニメーションに伴う影の揺れを調べるよう提案した。保存済みの雨夜の往復について、同じ世界座標の草130地点の自己影の中央値を、カメラのXが等しい位置で比較した。往路と復路の違いの中央値は1.22 m区間全体の自己影の変化量に対し、通常歩行で10.2%、しゃがみ歩きで6.7%だった。各方向を線形補間しており、入力間隔は通常で最大22.9 cm、しゃがみで最大6.9 cm。独立した手足の姿勢は記録していない。人物の輪郭を簡略化するかの判断には、目線の軌道と光源を合わせて手足のアニメーションだけを切り替える比較が残る。[Fableの原文](advisor.txt)・[往復の比較](walk-direction.json)・[元の測定](../2026-11-23-wet-oak-motion/components.json)
