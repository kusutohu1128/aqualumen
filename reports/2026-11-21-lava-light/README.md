# 洞窟の溶岩が落とす影

**1.9.0プレビュー3** では、天然洞窟の岩棚で魂の松明を置き、水で25マスの溶岩を黒曜石に変えた。広い溶岩溜まりでも松明の色を保つ。昼の白樺は同じ樹皮を消灯、松明、魂の松明で照合した。[洞窟の三場面](cavern/ordered-survival/cavern-light.jpg) · [白樺の比較](wall-v190/birch-release-comparison/birch.jpg) · [配布ZIP](../../dist/Aqualumen-1.9.0-preview.3.zip)

溶岩の前に半透明のガラス表示エンティティを出すと、旧方式ではガラス越しの壁が不自然に暗くなることを、Claudeの指摘から再現した。照明を計算してから半透明の色を重ねる順序に直した。ガラス左面と隣の壁の赤の差は、画素ごとに計算する比較用描画で−3.11、修正前−46.20、修正後−3.01階調だった。実機はIris 1.8.8とRTX 3080 Tiを使った。[三方式の実画面](wall-v190/glass-order-comparison/glass.jpg) · [同じ領域の表示RGB](wall-v190/glass-order-comparison/glass.json) · [Irisの描画順](https://shaders.properties/current/reference/shadersproperties/ordering/#separateentitydraws)

プレビュー3のZIPをソースから二度生成し、実機で読んだパックとバイト単位で一致した。通常版1.8.0も従来のZIPと一致する。既定のAqualumen Labでは1.8.0とphysics 0.2を選び、コンパイル用Mod 0.3.0は無効状態でプレビューと一緒に配置した。[配布物と検査の記録](preview3.json) · [Labの通常設定](wall-v190/preview3-lab.json)

## 試作の経過

1.8.0で、天井のある石の部屋を作り、同じ白壁を消灯・溶岩一マス・溶岩九マスで撮影した。溶岩と壁の間の石柱を立てたり外したりしてもカメラは同じ位置にある。すべての地形操作は確認用ワールドのコピーで行った。[実ゲームの比較](baseline-180/lava-wall.jpg) · [RTX 3080 Tiでの撮影条件と画像](baseline-180/complete.json)

一マスの溶岩からの直線がすべて石柱を通る壁を、座標であらかじめ選んだ。2,453点の表示値を調べると、消灯時との差の中央値は、柱を外したときに赤が77、柱を立てても68残った。溶岩にはMinecraftのブロック光が使われている。表示値には間接光と露出も含まれるので、この二つの画像だけで直射成分の割合は決まらない。[石柱と光路の定義、表示色の測定結果](baseline-180/wall-light.json)

次の対象は、溶岩の実際の発光面と面積、柱の左右から漏れる光、反射した光を個別に扱うこと。光源一個分の枠を溶岩一マスごとに消費すると、広い流れで隣の松明を押し出してしまう。配布中の1.8.0の動作は上の実測で確認できる。

通常と同じRTXの描画だけを使う私設の観測版で、溶岩が本当に形状として渡るかも確認した。Iris 1.8.8は追加画像の総数を16枚に制限し、現行パックはすでに16枚を使用していた。第2案ではこの場面で使われない水中専用アトラスの一部に観測値を記録した。石の床では0セル、溶岩一マスでは1セル、九マスでは9セル、床に戻すと0セルに戻った。上向き面の四隅が実データから採れ、静止した一マスの高さは各隅とも約0.888ブロックだった。これは本物の発光面を後の照明計算に渡せることの確認。1.8.0の通常配布には観測版を入れていない。[実ゲームで読んだ面・四隅・消灯対照](captured-shore-slots/faces.json)

次の実地比較に使う候補は、配布した森と同じシードの地下で見つかった。通常プレイの保存チャンク内の高さ−55に、上が空洞に面した溶岩が30マス連続しており、凝灰岩の足場 (543.5, −52, 376.5) から中央の25マスへ直線が通る。候補の選定は保存地形からの計算で、この地点の改良版をゲーム内で撮影するのは次の段階になる。[自然生成の溶岩溜まりの座標と根拠](natural-pool.json)

面そのものの明るさを計算するGLSL試作では、受け側の面に隠れる部分を切り、発光する三角形が占める立体角を積分した。水平な溶岩の至近距離、斜めの面、垂直の流れ、裏側、継ぎ目を含む20条件で、独立した面積積分（各三角形25,600点）と比較した。照度の最大絶対誤差はRTX 3080 Tiで1.05×10⁻⁶、llvmpipeで2.89×10⁻⁶。光源の放射輝度を1、半球全体から届く照度をπとした値。ここでは間の石や葉を入れる前の面光源を検証した。[GLSL試作](area-shader/lava_irradiance.glsl) · [実行条件と結果](area-shader/results.json) · [Heitzらによる多角形光源の積分](https://eheitzresearch.wordpress.com/415-2/)

この比較用の石柱については、壁の各点から見た溶岩面のうち、柱と床の縁で隠れる部分を切り取り、残る直射光を積分できた。壁の中央では直射光がゼロになる。同じ壁の縁 (203.19, 176.05, 366) では、一マスの溶岩なら柱を外したときの24%、九マスなら44%が届く。独立した面積積分（各条件147,456点）に対する最大差は、柱を外したときの照度の0.21%だった。GLSL試作はRTX 3080 Tiとllvmpipeの両方で171条件を通過した。図は直射光の計算結果で、1.8.0の実ゲーム画像は冒頭に掲載している。[直射光の比較図](area-shader/pillar-visibility.png) · [一本の柱を扱うGLSL](area-shader/lava_pillar.glsl) · [RTX](area-shader/pillar-nvidia.json) · [llvmpipe](area-shader/pillar-mesa.json) · [数値対照](area-shader/pillar-results.json)

Claude Opusが現行コードを読み、溶岩が144マスに広がる場合をCPUで計算した。一マスずつ松明と同じ枠に登録する案では、松明が届く55地点中15地点で、その松明が計算対象から外れた。次の実装では溶岩面を独立して扱う。溶岩の流れをせき止め、その手前に残した松明の火が同じ石を照らし続けるかを実ゲームで確認する。[Claudeの調査と設計案](claude-area-source/NOTES.md) · [CPU計算の条件と結果](claude-area-source/receipt.json)

## 溶岩と松明を同時に照明する開発版

溶岩面のリストと松明のリストを個別に確保し、同じ受光面に届く光を加算する実装を作った。RTXの実プログラムでは、一マス・九マスとも柱の真裏の直射はゼロ、柱の縁では開放時の24.4%・43.5%だった。九マスの溶岩に松明を加えた4地点の照度は、それぞれを単独で点けた結果の和と相対差6×10⁻⁸未満で一致した。144マスの溶岩と松明14本を同時に置いたケースでは、全512領域の松明リストが、同じ松明だけを置いた対照とビット単位で一致した。以下のGPU測定は照明成分だけを読んでいる。[計算方法と比較条件](optics-v190/README.md) · [光源の捕捉から受光面までのRTX測定](optics-v190/preview5-corrected-reference.json) · [llvmpipeでの照合](optics-v190/preview5-mesa-transport.json)


## 実ゲームの石柱と天然洞窟

1.9.0プレビュー2で同じ部屋を10場面撮影した。一マスの溶岩と白壁の間に石柱を戻すと、陰の赤みが下がる。九マスの溶岩を柱で遮り、壁側に魂の松明を置くと青が戻る。天然洞窟にも同じ計算を持ち込むと、1600×900のF3表示は1〜2 FPSで、歩行の確認を中断した。[RTXの同一視点比較](wall-v190/rim-rtx-compare/torch-with-lava.jpg) · [10場面の実行記録](wall-v190/sealed-link-rc2b-native/complete.json) · [天然洞窟の実行記録](cavern/obsidian-rc2/complete.json)

溶岩が見えない白樺林でも、2560×1440・12チャンク・同じ私設VirtualGL経路で、消灯・松明・魂の松明の平均は、1.8.0で44.3 / 28.3 / 29.7 FPS、プレビュー2で15.9 / 11.8 / 11.8 FPSだった。各条件は約10秒。通常のLabでは1.8.0を選択している。[1.8.0のフレーム記録](wall-v190/birch-stable/timing.json) · [プレビュー2のフレーム記録](wall-v190/birch-rc2/timing.json)
