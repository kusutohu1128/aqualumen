# Remove the lava-free fullscreen cost — plan for Devin, HEAD `64f4379`

## Baseline and question

Measure where preview 3 introduced work, then apply the smallest demonstrated fix to preview 8 as an unpublished preview 9. The acceptance reference for pixels is p8. Stable is the historical performance control. Lamp ray traversal, diffuse-hit traversal and radiance cascades are outside this change.

- On the lava-free birch-off camera, mean GPU times (1.8.0 → p3) were 0.632 → 2.001 ms for `quad/composite`, 0.380 → 1.837 for `quad/deferred`, and 0.025 → 0.417 for `dispatch/shadowcomp2`. The CPU render-return interval increased 5.249 ms. The two fullscreen draws alone account for about 2.83 ms. [Measured ranges](../reports/2026-11-22-gpu-profile/README.md)
- I traced the actual ZIP entries. Composite's entry source is identical. Of the common files in its recursive include graph, **only `lib/local_lighting.glsl` changes**, via `lib/illumination.glsl`; the graph acquires lava transport/intersection code. The underwater branch calls waterIncidentIrradiance → lampLighting. The dry atmospheric branch uses diffuseSkyIrradiance. Textual inclusion leaves open which code survives preprocessing and what the driver compiles.
- Deferred adds the local-light/bounce/leaf receiver, C15 reads and a fifth MRT (C14 luminance read/write). It **already** tests `depth < .999999 && directSun.a < -.5`. Terrain marks C5 alpha −1/−2 only when a receiver has uncached lava groups. A second fragment-level zero test might save nothing. The shadowcomp2 change also trades one invocation looping over four patches for four z lanes and writes an extra RGBA16F bank.

## Candidate design and placement

- Use the existing **whole captured grid** flag. `captureLava` atomically sets `lampIndexImage[0,72]` after marking a group; Iris declares this R32UI image clear-per-frame. Shadowcomp1 already reads it before publishing the 512 per-tile lists. The p8 canopy allocation appends data starting at row 73. Verify clear → shadow capture → image/texture-fetch barrier → current-frame consumers, including first frame, teleport and pipeline reload. A zero camera-tile neighbour count cannot certify all visible receivers.
- Prefer reading `usampler2D aqualumenRawIndex` at (0,72) once per fullscreen **vertex** or once per compute workgroup. Validate integer sampler binding and stage limits on both renderers. If a sampler cannot be bound, publish 0/1 from tile 0 lane 0 of shadowcomp1 into `lavaSourcesAddress(0,1023)` of the existing 512×2048 R32F field (header 0, at most 1000 source IDs). Prove non-overlap, unconditional overwrite and visibility before using it. Reserve no 17th custom image. An unsupported layout takes the original path.
- Start with the one-pass fix if source/pragma isolation proves it restores the budget with the required image equality. For example, isolate dry aerial/sky code from the area-light include at compile time; preserve the NVIDIA compiler treatment of the actual lava program. Do not globally disable the compiler or remove the underwater lamp term.
- If the expensive linked shader persists on idle frames, use two **separately linked**, complementary fullscreen variants. One quad renders, the other has all vertices clipped outside the same clip plane by the uniform captured-lava flag. Heavy is the original p8 fragment program when any lava was captured. Cheap deferred runs the identical sky, contact AO, depth, opaque snapshot, material and direct-Sun logic and copies terrain C14; only the impossible pending solve and C15 fetch disappear. Cheap composite retains dry aerial, dimension fog, underwater caustics, scatter, and placed/carried lamp terms; compile out only area-emitter work proven zero. Keep derivatives before divergent tests, and preserve math order/precision. Factor shared source rather than maintaining two versions of sky or fog.
- For that split, the first draw writes the alternate FBO with explicit `flip.<pass>.colortexN=false` for **every** output; the second uses the same read/write sides and does the normal flip. Pinned CompositeRenderer consults the explicit false before flipping. Prove actual FBO IDs, sampler sides, dimensions, no implicit clear between draws, disjoint read/write, full coverage and exactly one flip, including C14. No discard into an uninitialized alternate texture. Keep both deferred draws before translucent rendering. Place both composite draws before glow extraction. Reject this design if the live binding trace contradicts it.
- In shadowcomp2, keep all four outgoing lamp/first-bounce patches, lower-bank RGBA and their clears. On empty frames omit only work for the face cache at y+512. Gate every cache reader, including neighbour/validity reads, so stale data cannot escape; if needed synthesize the p8 empty diffuse/validity value from the freshly written lower-bank lit alpha. On reappearance write **all** upper-bank patches, including invalid ones, before reading. Test poison and repeated transitions. Record dead upper-bank bytes separately from visible outputs; the existing dense-lava removal oracle must still return negative alpha. If private cache semantics cannot be preserved, retain the write and report its measured cost separately.
- **Ship as a candidate-only last overlay** `release/idle-preview/shaders/` after eye. Add `--idle-preview` in `tools/build.py`; stage exclusively with `python3 tools/build.py --idle-preview --output build/lava-idle/Aqualumen-1.9.0-preview.9.zip`. Keep prior source layers and published archives as reproducible references. Add an entry-owner/hash test with a reviewed allowlist; privately rebuild stable and p3–p8 and match their published ZIP hashes. Defer flattening: a topmost delta has no higher writer, and a whole-stack migration would obscure this performance experiment.

## Proof and decision

1. Add `tools/lava-idle-probe.h`, wire `--lava-idle-probe <p8-shaders>` in `tools/glcheck.cpp` and `make check-idle` in `Makefile`. Add CPU tests for build provenance, diagnostic single-factor diffs, per-program pragma and slot/range remapping. Red first: the current p8 control gives the correct pixels but executes the heavy fullscreen program and upper-bank store in an empty scene. Require that failure specifically; a missing filename is insufficient.
2. In a diagnostic-only replay count active heavy **fragments/work**, independent of the profiler's submitted-quad count (a clipped draw is still submitted). Use occlusion queries on the split, or test-only path counters for a single program and the cache writer. Red must distinguish a heavy-capable fragment invocation on p8 from a lean invocation on p9 even when neither enters the pending block. Require zero heavy invocations on the specialized empty route and zero upper-bank writes for the cache optimization; on the full route a known pending lava receiver must execute and light up. Instrumented builds never supply timings.
3. Render p8 and candidate from identical seeded textures, camera, frameTime, exposure history and resource state on each driver. Compare native attachment bytes after deferred (C0/4/8/10/14), composite C0, final display, and exposure history. Require bitwise equality separately on each renderer for lava-free air/sky, birch off/torch, two lamps, underwater, wet leaves, hand/held lights and dimension fog. Require the same equality **with lava present** in the actual one-/nine-cell lava-room probe with pillar, torch, visible/occluded source and dense face-cache scene.
